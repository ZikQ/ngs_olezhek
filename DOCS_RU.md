# ngs_olezhek: документация разработчика

ngs_olezhek это фреймворк для веб-приложений на Rust и Lua. Сервер пишется на Rust (поверх [axum](https://docs.rs/axum)), а весь интерфейс в браузере описывается на Lua 5.4 в стиле `vgui` из Garry's Mod: панели, `Initialize`, `Paint`, `DoClick`, `Dock`. HTML, CSS и JavaScript остаются внутри фреймворка, писать их не нужно.

Документация рассчитана на разработчика, который не знаком с вебом. Везде, где метод или понятие пришло из HTML, CSS или JavaScript, есть пояснение, что это такое в браузере. Общий словарь собран в разделе [Основы веба для новичков](#основы-веба-для-новичков).

## Что это и как устроено

Минимальное приложение выглядит так.

Rust:

```rust
use ngs_olezhek::App;

#[tokio::main]
async fn main() {
    App::new().lua("lua").serve("127.0.0.1:3000").await.unwrap();
}
```

Lua (`lua/pages/home.lua`):

```lua
local PAGE = {}
PAGE.Route = "/"

function PAGE:Initialize()
    local count = 0
    local label = ui.Create("Label", self, { Text = "Нажатий: 0" })
    ui.Create("Button", self, {
        Text = "Нажми",
        DoClick = function()
            count = count + 1
            label:SetText("Нажатий: " .. count)
        end,
    })
end

ui.Register("HomePage", PAGE, "Page")
```

Что происходит, когда пользователь открывает сайт:

1. Rust-сервер отдаёт короткую страницу-оболочку, клиентский рантайм (WebAssembly) и пакет с Lua-байткодом вашего приложения.
2. Браузер запускает рантайм. В нём лежит интерпретатор Lua ([omnilua](https://crates.io/crates/omnilua), написан на Rust и собран в WebAssembly). Рантайм выполняет ваши Lua-файлы.
3. Каждая панель (`Label`, `Button`, `TextEntry`...) превращается в обычный элемент страницы. Размеры и расположение панелей отображаются на CSS flexbox и grid, поэтому вёрстку делает сам браузер.
4. Данные приложение получает у вашего Rust-сервера обычными HTTP-запросами (`http.Get`, `http.Post`), а сервер отвечает JSON.

Три вещи, которые полезно знать сразу:

- Исходный Lua-код до браузера не доезжает: сервер компилирует его в байткод. Это затрудняет чтение кода, но не защищает его. Секреты (ключи, пароли) в Lua-файлах хранить нельзя.
- Код приложения считается доверенным. Защита построена вокруг недоверенных данных (то, что пришло с сервера или ввёл пользователь) и недоверенного Lua-кода (плагины, пользовательские скрипты), см. [Безопасность](#безопасность) и [Песочница](#песочница-для-чужого-кода).
- Синтаксис обычный Lua 5.4: `~=` вместо `!=`, `--` для комментариев. Диалект GLua (`!=`, `&&`, `//` комментарии) не поддерживается.

## Быстрый старт

### Что понадобится

| Инструмент | Зачем | Как поставить |
| --- | --- | --- |
| Rust 1.88 или новее | сервер и сборка рантайма (edition 2024) | [rustup.rs](https://rustup.rs) |
| Цель `wasm32-unknown-unknown` | клиентский рантайм собирается в WebAssembly | `rustup target add wasm32-unknown-unknown` |
| `wasm-bindgen-cli` версии 0.2.129 | соединяет WebAssembly с JavaScript-оболочкой | `cargo install wasm-bindgen-cli --version 0.2.129` |
| `wasm-opt` из [binaryen](https://github.com/WebAssembly/binaryen) (необязательно) | уменьшает размер рантайма в release-сборке | пакетный менеджер ОС |
| Компилятор C (необязательно) | только для функции `sqlite` (сессии в SQLite) | MSVC Build Tools, gcc или clang |

Версия `wasm-bindgen-cli` должна совпадать с версией библиотеки `wasm-bindgen`, которую использует фреймворк, иначе сборка упадёт. Если `wasm-opt` не найден, сборка предупредит об этом и отдаст неоптимизированный рантайм.

Клиентский рантайм собирается автоматически скриптом `build.rs` при первой сборке вашего проекта. Первая сборка заметно дольше обычной, потому что вместе с рантаймом компилируется интерпретатор Lua.

Если собирать рантайм на этой машине нельзя (например, в CI без `wasm-bindgen`), задайте переменную окружения `NGS_RUNTIME_DIR` с путём к папке с готовыми файлами `runtime.js` и `runtime_bg.wasm`. Тогда сборка рантайма пропускается.

### Новый проект

Фреймворк пока не опубликован на crates.io, подключите его по пути или из git-репозитория:

```toml
[package]
name = "my_site"
version = "0.1.0"
edition = "2024"

[dependencies]
ngs_olezhek = { path = "../ngs_olezhek" }
axum = "0.8"
serde = { version = "1", features = ["derive"] }
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }
```

`axum` и `serde` нужны вашему крейту напрямую: макросы `#[get]`, `#[post]` и `#[derive(LuaType)]` генерируют код, который ссылается на них по имени. Если вы используете WebSocket, добавьте в `axum` функцию `ws`, а для приёма файлов функцию `multipart`.

Структура проекта:

```text
my_site/
  Cargo.toml
  src/main.rs
  lua/
    pages/
      home.lua
```

`src/main.rs`:

```rust
use ngs_olezhek::App;

#[tokio::main]
async fn main() {
    let app = App::new().title("Мой сайт").lua("lua");
    if let Err(e) = app.serve("127.0.0.1:3000").await {
        eprintln!("{e}");
        std::process::exit(1);
    }
}
```

`lua/pages/home.lua`:

```lua
local PAGE = {}
PAGE.Route = "/"
PAGE.Title = "Главная"

function PAGE:Initialize()
    self:SetGap(12)
    self:DockPadding(24, 24, 24, 24)

    local label = ui.Create("Label", self, { Text = "Нажатий: 0" })
    local count = 0
    ui.Create("Button", self, {
        Text = "Нажми",
        DoClick = function()
            count = count + 1
            label:SetText("Нажатий: " .. count)
        end,
    })
end

ui.Register("HomePage", PAGE, "Page")
```

Запустите `cargo run` и откройте <http://127.0.0.1:3000>. Измените любой `.lua`-файл и сохраните: в режиме разработки страница обновится сама.

### Что здесь произошло

- `App::new().lua("lua")` указывает серверу папку с Lua-файлами. Относительный путь считается от папки, из которой запущена программа.
- Файл `home.lua` выполнился в браузере при загрузке. Он зарегистрировал класс `HomePage` на базе встроенного класса `Page` и привязал его к адресу `/`.
- Когда пользователь открыл `/`, роутер создал страницу `HomePage` и вызвал её метод `Initialize`.
- `ui.Create("Label", self, {...})` создал надпись внутри страницы. В браузере это HTML-элемент `<span>`.
- `DoClick` вызывается при клике на кнопку. Внутри обработчика можно менять панели и делать HTTP-запросы.
- Кнопка получилась на всю ширину страницы: в столбце элементы по умолчанию растягиваются поперёк. Как это изменить, описано в разделе [Раскладка и стили](#раскладка-и-стили).

### Две полезные привычки с самого начала

Подключите автодополнение. В режиме разработки сервер при старте записывает описание всего Lua API в `lua/.ngs/ngs.lua` и создаёт `.luarc.json` в корне проекта. Установите расширение [Lua Language Server](https://luals.github.io) (в VS Code оно называется «Lua», автор sumneko), и редактор начнёт подсказывать методы и типы. Подробности в разделе [Инструменты разработчика](#инструменты-разработчика).

Добавьте `.ngs/` в `.gitignore`: эти файлы создаются заново при каждом запуске.

### Режимы dev и release

По умолчанию режим зависит от профиля сборки: `cargo run` включает dev, `cargo run --release` включает release. Переопределить можно методом `App::dev(true)` или `App::dev(false)`.

| | dev | release |
| --- | --- | --- |
| Сборка Lua | при каждой загрузке страницы файлы читаются с диска | один раз при старте сервера |
| Синтаксическая ошибка в Lua | показывается в браузере | сервер не запускается, `serve` возвращает ошибку |
| Горячая перезагрузка | да, через соединение `/_ngs/live` | нет |
| Lua-ошибки | красные плашки поверх страницы и консоль браузера | консоль браузера; можно отправлять на сервер |
| Номера строк в трассировках | есть | нет (байткод очищен от отладочной информации) |
| Cookie сессий | без флага `Secure` | с флагом `Secure` и префиксом `__Host-` |
| Заголовок HSTS | нет | `max-age=31536000` |
| Файлы для редактора (`.ngs/`) | пишутся при старте | не пишутся |

В Lua-коде признак режима доступен как глобальная переменная `DEV` (`true` или `false`).

## Основы веба для новичков

Этот раздел объясняет понятия, на которые опирается остальная документация. Если вы уже знаете веб, можете пропустить его и вернуться по ссылке из нужного места.

### Как открывается страница

Браузер (клиент) и сервер общаются по протоколу HTTP: клиент отправляет запрос, сервер возвращает ответ.

- URL это адрес: `https://example.com:3000/users/5?tab=info#top`. Здесь `https` схема, `example.com` хост, `3000` порт, `/users/5` путь, `tab=info` строка запроса (query), `#top` фрагмент. Хост, схема и порт вместе называются origin (источник).
- Метод запроса говорит, что нужно сделать. `GET` прочитать, `POST` создать или отправить данные, `PUT` и `PATCH` изменить, `DELETE` удалить. `GET` не должен менять данные на сервере.
- Статус ответа это число: `200` успех, `204` успех без тела, `301` и `302` переадресация, `400` плохой запрос, `401` нужно войти, `403` запрещено, `404` не найдено, `422` данные не прошли проверку, `429` слишком много запросов, `500` ошибка сервера.
- Заголовки (headers) это пары «имя: значение» с метаданными. Например `Content-Type: application/json` говорит, что тело запроса это JSON.
- JSON это текстовый формат данных: объекты `{"name": "Ann"}`, массивы `[1, 2, 3]`, строки, числа, `true`, `false`, `null`. Фреймворк сам превращает его в таблицы Lua и обратно.
- Одностраничное приложение (SPA, single-page application) загружается один раз, а дальше само меняет содержимое окна и адрес в строке браузера, не перезагружая страницу. Именно так работает ngs_olezhek.

### HTML: элементы, теги и атрибуты

HTML описывает содержимое страницы как дерево элементов. Каждый элемент записывается тегом: `<button>Нажми</button>`. Теги бывают разные: `<div>` (простой блок), `<span>` (кусок текста), `<button>` (кнопка), `<input>` (поле ввода), `<img>` (картинка), `<a>` (ссылка) и так далее.

У элемента есть атрибуты: `<a href="/about" target="_blank">`. Атрибуты задают адрес ссылки, подсказку (`title`), начальное значение и т. п.

Дерево элементов живой страницы называется DOM (Document Object Model). Браузер строит DOM из HTML и позволяет менять его программно. Во фреймворке вы не работаете с DOM напрямую: каждая панель владеет одним элементом, а методы панели меняют этот элемент.

Соответствие встроенных элементов HTML-тегам:

| Класс панели | HTML-элемент | Комментарий |
| --- | --- | --- |
| `Panel`, `Row`, `Column`, `Grid` | `<div>` | универсальный контейнер |
| `Label` | `<span>` | текст |
| `Button` | `<button>` | кнопка |
| `TextEntry` | `<div>` с `<input type="text">` или `<textarea>` внутри | поле ввода |
| `CheckBox` | `<label>` с `<input type="checkbox">` | флажок |
| `ComboBox` | `<div>` с `<select>` | выпадающий список |
| `Slider` | `<div>` с `<input type="range">` | ползунок |
| `NumberWang` | `<div>` с `<input type="number">` | числовое поле |
| `ProgressBar` | `<div>` с `<progress>` | полоса прогресса |
| `Image` | `<img>` | картинка |
| `Link` | `<a>` | ссылка |
| `ScrollPanel` | `<div>` с прокруткой | прокручиваемая область |
| `Page` | `<main>` | страница |
| `Frame` | `<dialog>` | окно |
| `Menu` | `<div popover>` | всплывающее меню |
| `Popover` | `<div popover>` | всплывающий слой с любым содержимым |
| `FileInput` | `<div>` с `<input type="file">` | выбор файлов |
| `Badge`, `Status`, `Avatar`, `Meter`, `Segmented`, `Spinner`, `ListView` | `<span>` или `<div>` | готовые элементы оформления, см. [Набор компонентов](#набор-компонентов) |
| `Select`, `DatePicker` | `<button>` и `<div popover>` | выбор из списка и выбор даты |
| `Sparkline`, `LineChart`, `BarChart`, `DonutChart` | `<div>` (часть с `<canvas>`) | графики |
| `Dialog` | `<dialog>` | окно с шапкой, телом и кнопками |

Дополнительно для доступности (чтобы страницей могли пользоваться скринридеры и клавиатура) у элементов есть роли и атрибуты ARIA: `role="tab"`, `aria-selected="true"` и подобные. Встроенные элементы расставляют их сами, а свои можно задать методом `SetAttr`.

### DOM: атрибуты и свойства

У элемента в браузере есть два близких, но разных набора данных.

- Атрибут это то, что написано в HTML: `<input value="abc">`. Это начальное значение.
- Свойство (property) это текущее состояние объекта элемента: `input.value` меняется, пока пользователь печатает, а атрибут `value` остаётся прежним.

Во фреймворке им соответствуют `Panel:SetAttr` / `Panel:GetAttr` и `Panel:SetProp` / `Panel:GetProp`. Кроме них есть `Panel:Invoke` для вызова встроенных методов элемента (`play`, `pause`, `select`...). Все три метода работают по белому списку: нельзя задать обработчик события строкой, стиль или адрес вида `javascript:`, см. [Безопасность](#безопасность).

### CSS: стили, единицы и состояния

CSS описывает внешний вид элементов набором пар «свойство: значение»: `color: red; padding: 8px; border-radius: 6px`. Фреймворк предоставляет удобные методы (`SetBackgroundColor`, `SetRadius`, `SetBorder`), а для всего остального есть `Panel:SetStyle`, куда можно передать любое разрешённое CSS-свойство. Имена можно писать как в CSS (`border-radius`) или в camelCase (`borderRadius`).

Единицы измерения:

- `px` (пиксель). Число в Lua (`SetWide(200)`) всегда означает пиксели.
- `%` доля размера родителя: `"50%"`.
- `fr` доля свободного места в сетке: `"1fr"`, `"2fr"`.
- `fit-content` по размеру содержимого, `auto` решает браузер.
- `em` размер, привязанный к размеру шрифта: `"2em"`.

Строки с единицами передаются в кавычках: `panel:SetWide("50%")`.

Цвет задаётся объектом `Color(r, g, b, a)`, где каждая компонента от 0 до 255. Параметр `a` это непрозрачность: 255 непрозрачный, 0 невидимый.

Блочная модель. Каждый элемент это прямоугольник из слоёв, изнутри наружу: содержимое, `padding` (внутренний отступ), `border` (рамка), `margin` (внешний отступ вокруг рамки). Во фреймворке `DockPadding(l, t, r, b)` задаёт внутренний отступ, `DockMargin(l, t, r, b)` внешний. Порядок аргументов: слева, сверху, справа, снизу.

Псевдоклассы это состояния элемента: `:hover` курсор над элементом, `:active` кнопка мыши зажата, `:focus` элемент в фокусе (принимает ввод с клавиатуры), `:disabled` отключён. Во фреймворке им соответствуют `SetStyleHover`, `SetStyleActive`, `SetStyleFocus`, `SetStyleDisabled`. Браузер сам применяет их без вызова Lua, поэтому наведение мыши ничего не стоит.

Прочие понятия, которые встретятся:

- `overflow` что делать, если содержимое больше элемента: `hidden` обрезать, `auto` и `scroll` показать полосы прокрутки.
- `position`: `relative` обычное положение, `absolute` по координатам внутри родителя, `fixed` по координатам окна браузера. Каждая панель во фреймворке уже является точкой отсчёта для дочерних панелей с абсолютным положением (`SetPos`).
- `z-index` порядок наложения: у кого больше, тот сверху (`SetZPos`).
- `opacity` прозрачность всего элемента от 0 до 1 (`SetAlpha` принимает 0..255).
- `transition` плавное изменение свойства за заданное время (`SetTransition`).
- `transform` сдвиг, поворот, масштаб, наклон без влияния на соседей (`SetTransform`).
- `box-shadow` тень, `linear-gradient` градиент.
- `cursor` вид указателя мыши над элементом (`SetCursor`).
- CSS-переменные (`--ngs-accent`) это именованные значения, на которые ссылается стиль через `var(--имя)`. Тема оформления фреймворка (`ui.SetSkin`) меняет именно их, а свои переменные приложения объявляет `ui.SetVars`, см. [Тема оформления](#тема-оформления).

### Flexbox и grid

Это два способа расположить дочерние элементы внутри родителя. Фреймворк использует их для всей раскладки.

Flexbox расставляет детей в одну линию (ряд или столбец):

```text
SetLayout(LAYOUT_ROW)         SetLayout(LAYOUT_COLUMN)
[ A ][ B ][ C ]               [ A ]
                              [ B ]
                              [ C ]
```

- Главная ось это направление линии (горизонталь у ряда, вертикаль у столбца). Расположение вдоль неё задаёт `SetJustify` (`JUSTIFY_*`).
- Поперечная ось перпендикулярна главной. Расположение вдоль неё задаёт `SetAlign` (`ALIGN_*`). По умолчанию дети растягиваются на всю поперечную ось (`ALIGN_STRETCH`).
- `SetGap` задаёт промежуток между детьми, `SetGrow` позволяет ребёнку занять оставшееся свободное место.

Grid (сетка) расставляет детей по ячейкам таблицы из строк и столбцов: `SetLayout(LAYOUT_GRID)` и `SetColumns(3)`. Метод `Dock`, привычный по Garry's Mod, во фреймворке реализован как одна общая сетка, см. [Раскладка и стили](#раскладка-и-стили).

### События браузера

Событие это уведомление браузера о том, что что-то произошло: клик, наведение мыши, нажатие клавиши, изменение текста в поле, получение фокуса, изменение размера окна. Во фреймворке события приходят в ваши методы панели: `DoClick`, `OnCursorEntered`, `OnKeyCodePressed`, `OnValueChange` и т. д. Полный перечень в разделе [Панели](#панели).

Названия клавиш в `OnKeyCodePressed` совпадают с JavaScript-свойством `KeyboardEvent.key`: `"Enter"`, `"Escape"`, `"ArrowLeft"`, `"a"`, `" "` (пробел).

### Термины безопасности

- XSS (межсайтовый скриптинг): чужой код попадает на вашу страницу и выполняется с вашими правами. Типичный путь: пользовательский текст вставляется в страницу как HTML, или в ссылку попадает адрес `javascript:...`. Фреймворк выводит текст как текст и проверяет адреса и атрибуты.
- CSRF (подделка межсайтового запроса): вредный сайт заставляет браузер пользователя отправить запрос на ваш сайт, а браузер сам приложит cookie. Защита включена по умолчанию.
- Same-origin policy (политика одного источника): браузер не даёт странице читать ответы чужого origin.
- CORS: правила, по которым сервер разрешает страницам другого origin читать его ответы.
- CSP (Content Security Policy): заголовок ответа, в котором сервер перечисляет, откуда странице можно грузить скрипты, картинки и данные.
- Cookie-флаги: `HttpOnly` скрывает cookie от скриптов страницы, `Secure` отправляет её только по HTTPS, `SameSite` запрещает прикладывать её к запросам с чужих сайтов.
- Сессия: сервер запоминает, кто вошёл; браузеру отдаётся только случайный идентификатор в cookie.
- Rate limit (ограничение частоты): сервер отвечает `429`, если запросов слишком много.

## Структура приложения

### Папка с Lua-кодом

`App::lua("lua")` указывает папку с исходниками интерфейса. Правила сбора файлов:

- берутся все файлы `*.lua`, включая вложенные папки;
- файлы и папки, имя которых начинается с точки (`.ngs`, `.git`), пропускаются;
- имя файла внутри приложения это путь от папки через `/`: `pages/home.lua`, `vgui/card.lua`;
- сначала выполняются файлы из папки `autorun/`, затем все остальные в алфавитном порядке путей.

Все файлы выполняются один раз при загрузке страницы в браузере (то есть у каждой вкладки свой запуск). `local`-переменные видны только внутри своего файла, глобальные переменные общие для всех файлов. Файл может вернуть значение через `return`, а другой файл может получить его функцией `include`:

```lua
-- lua/shared/config.lua
return { pageSize = 20 }
```

```lua
local config = include("shared/config.lua")
```

`include(path)` выполняет файл при первом вызове и запоминает результат, повторные вызовы возвращают то же самое. Путь пишется так же, как имя файла внутри приложения (`"shared/config.lua"`). Если файла нет, будет ошибка.

Особый смысл имеют только две папки, остальные вы называете как хотите.

| Папка | Назначение |
| --- | --- |
| `autorun/` | выполняется первой: шрифты, тема, хуки, регистрация маршрутов, настройки |
| `lazy/` | страницы, которые загружаются отдельно, при первом переходе на них |

Рекомендуемая раскладка:

```text
lua/
  autorun/
    theme.lua        шрифты, ui.SetSkin, глобальные хуки
    routes.lua       router.Lazy(...) для маршрутов с параметрами
  vgui/
    card.lua         свои классы панелей (ui.Register)
    default_page.lua общий лейаут и базовая страница
  lazy/
    index.lua        страница "/"
    profile.lua      страница "/profile/{id}"
  pages/
    not_found.lua    страница, которая нужна сразу (например, 404)
```

### Страницы, которые нужны сразу, и ленивые страницы

Обычный файл выполняется при загрузке. Если страница регистрируется в нём с полем `Route`, маршрут известен сразу:

```lua
local PAGE = {}
PAGE.Route = "/about"
function PAGE:Initialize() end
ui.Register("AboutPage", PAGE, "Page")
```

Для больших приложений лучше класть страницы в `lazy/`. Такой файл не входит в стартовый пакет: браузер скачивает его, когда пользователь впервые переходит на страницу. Стартовая загрузка становится быстрее. Правила:

- Адрес страницы выводится из имени файла: `lazy/index.lua` это `/`, `lazy/forms.lua` это `/forms`, `lazy/users/index.lua` это `/users`, `lazy/users/list.lua` это `/users/list`.
- Файл должен вернуть определение страницы: `return ui.Register("FormsPage", PAGE, "Page")` или просто таблицу `return PAGE` (тогда класс регистрируется сам на базе `PAGE.Base` или `Page`).
- Для адреса с параметрами (`/profile/{id}`) зарегистрируйте маршрут явно в `autorun/`: `router.Lazy("/profile/{id}", "ProfilePage", "lazy/profile.lua")`. Класс в файле должен называться так же, как во втором аргументе.
- Ленивые файлы выполняются позже остальных, поэтому в них можно использовать всё, что определено в обычных файлах (базовые классы, шрифты, тему).

Подробнее о маршрутах в разделе [Маршрутизация](#маршрутизация).

### Горячая перезагрузка (режим dev)

В режиме dev сервер следит за папкой `lua`. При сохранении файла браузер получает новую версию, и фреймворк:

1. выполняет файл заново, то есть перерегистрирует классы, объявленные в нём;
2. обновляет методы уже созданных панелей этих классов, потому что все панели класса используют одну общую таблицу методов;
3. перестраивает текущую страницу (`router.Reload`), если файл не регистрировал классов (например, шрифты или тема) или среди живых панелей есть экземпляры перерегистрированных классов. `Initialize` у существующих панелей сам не перезапускается, поэтому без перестройки изменения в нём не были бы видны;
4. вызывает хук `OnReload(имя_файла)` и пишет в консоль строку `[ngs] reloaded ...`.

Если сохранён файл с синтаксической ошибкой, ошибка появится на странице, а старая версия продолжит работать; после следующего удачного сохранения плашки с ошибками очищаются. Соединение с сервером тоже важно: если оно оборвалось и восстановилось, клиент решает, что сервер перезапускался, и перезагружает страницу.

### Окружение Lua

Это обычный Lua 5.4 с таким составом стандартной библиотеки:

| Есть | Нет |
| --- | --- |
| базовые функции (`print`, `pairs`, `pcall`, `load` только для текста...), `string`, `table`, `math`, `coroutine`, `utf8` | `io`, `os`, `package` и `require`, `bit32` |
| | `debug`, `string.dump`, `dofile`, `loadfile`, загрузка бинарных кусков через `load` (удалены намеренно, см. [Безопасность](#безопасность)) |

Вместо `require` используйте `include`. Вместо `os.clock` используйте `CurTime()`, вместо `os.time` и `os.date` модуль [`date`](#дата-и-время). К стандартным библиотекам добавлены помощники в духе Garry's Mod (`math.Clamp`, `string.Split`, `table.Copy`...), они описаны в разделе [Глобальные функции Lua](#глобальные-функции-lua).

Функция `print` пишет в консоль браузера (откройте её клавишей F12, вкладка Console).

### Куда попадают ошибки

Ошибка в обработчике (клик, таймер, `Initialize`...) не ломает страницу: она перехватывается и сообщается.

- В режиме dev ошибка показывается красной плашкой в правом нижнем углу окна и пишется в консоль. Клик по плашке закрывает её, одинаковые сообщения складываются в счётчик, одновременно видно не более 8 плашек.
- В режиме release ошибка пишется только в консоль браузера. Если включено отправление ошибок (по умолчанию включено, см. [Rust: сервер](#rust-сервер), `App::on_client_error`), браузер отправляет их на сервер.
- `ErrorNoHalt(...)` сообщает об ошибке так же, но не прерывает выполнение.

Сообщения в release приходят из байткода без отладочной информации, поэтому в трассировках нет номеров строк. Чтобы они были, запустите приложение с `App::strip(false)`.

## Панели

Панель (panel) это основной строительный блок интерфейса. Каждая панель владеет одним HTML-элементом, а её методы (`SetText`, `SetWide`, `Dock`...) меняют этот элемент. Панели образуют дерево: у каждой есть родитель и список детей. Вершина дерева это корневая панель (`ui.GetRoot()`), невидимый контейнер на всё окно. Страницы и окна создаются внутри неё.

### Создание панелей

```lua
local panel = ui.Create(класс, родитель, свойства)
```

| Аргумент | Что это |
| --- | --- |
| `класс` | имя класса панели: `"Button"`, `"Label"` или ваш собственный |
| `родитель` | панель, внутри которой создаётся новая; по умолчанию корневая панель |
| `свойства` | необязательная таблица, см. ниже |

Короткая запись `parent:Add(класс, свойства)` делает то же самое: `self:Add("Label", { Text = "Привет" })`.

Таблица свойств заменяет серию вызовов методов:

- Ключ, для которого у панели есть метод `Set<Ключ>`, вызывает этот метод после `Initialize`: `{ Text = "Hi" }` вызовет `SetText("Hi")`. Для `Dock`, `DockMargin` и `DockPadding` вызывается метод с тем же именем.
- Если значение это обычная таблица (без метатаблицы), для некоторых ключей она распаковывается в аргументы: `Size = { 200, 40 }` вызовет `SetSize(200, 40)`. Распаковываются `Size`, `Pos`, `MinSize`, `MaxSize`, `Border`, `Radius`, `Shadow`, `Gradient`, `Overflow`, `Gap`, `DockMargin`, `DockPadding`, `Transition`. Объекты `Color` и состояния не распаковываются.
- Если значение это `ui.State` или `ui.Computed`, свойство привязывается к состоянию (см. [Реактивное состояние](#реактивное-состояние)).
- Ключи без метода `Set<Ключ>` становятся полями панели до вызова `Initialize`, их можно читать как `self.Ключ`. Так передаются обработчики (`DoClick = function() ... end`) и любые ваши данные.
- Элементы массива (ключи 1, 2, 3...) это дети: готовые панели (они переносятся в новый родитель) или функции, которые получат панель и создадут детей сами.
- Ключ `Slot` выбирает слот родителя (см. ниже), `Slot = false` пропускает слоты и кладёт панель прямо в родителя.

```lua
local card = ui.Create("Panel", self, {
    Gap = 8,
    Size = { 300, 120 },
    BackgroundColor = Color(37, 40, 45),
    function(p) p:Add("Label", { Text = "Заголовок" }) end,
    ui.Create("Button", nil, { Text = "OK" }),
})
```

Класс, которого нет, вызовет ошибку `unknown panel class`.

### Свои классы панелей

Класс описывается таблицей методов и регистрируется функцией `ui.Register(имя, таблица, база)`:

```lua
local CARD = {}

function CARD:Initialize()
    self:SetGap(10)
    self:DockPadding(18, 16, 18, 18)
    self:SetRadius(10)
    self:SetBackgroundColor(Color(37, 40, 45))
    self.TitleLabel = ui.Create("Label", self, { Font = "DefaultBold" })
end

function CARD:SetTitle(text)
    self.TitleLabel:SetText(text)
end

ui.Register("Card", CARD, "Panel")
```

Теперь `ui.Create("Card", parent, { Title = "Привет" })` работает, и `Title` попадёт в `SetTitle`.

- Третий аргумент это имя базового класса. На практике он обязателен: класс без базы не получает методов `Panel`. Для обычных контейнеров база `"Panel"`, для кнопок `"Button"`, для страниц `"Page"`.
- Методы базового класса наследуются. Метод `Initialize` вызывается у всей цепочки, начиная с самого базового класса (как в vgui).
- Чтобы вызвать метод родителя из переопределённого, обратитесь к классу по имени: `ui.GetClass("Button").SetText(self, text)`. Поле `self.BaseClass` тоже существует, но в многоуровневых цепочках оно указывает на базу самого конкретного класса, а не того, чей метод выполняется, поэтому через имя надёжнее.
- `ui.GetClass(имя)` возвращает таблицу класса, `ui.Exists(имя)` проверяет, зарегистрирован ли он, `ui.IsPanel(v)` проверяет, что `v` это панель.
- Повторная регистрация класса с тем же именем заменяет методы у уже созданных панелей. Это основа горячей перезагрузки.
- Поля, имена которых начинаются с `__`, принадлежат фреймворку. Не используйте такие имена для своих данных.
- Имя класса можно прочитать как `self.ClassName` или `self:GetClassName()`.

Зарезервированные поля класса:

| Поле | Значение |
| --- | --- |
| `Base` | имя базового класса (задаётся третьим аргументом `ui.Register`) |
| `Tag` | HTML-тег для собственного класса, если база не определяет его, например `Tag = "video"`. Допустимы теги из строчных букв и цифр и пользовательские теги с дефисом. Теги, которые выполняют код или загружают документы (`script`, `style`, `iframe`, `object`, `svg`, `form` и подобные), запрещены |
| `BindDefault` | имя свойства, которое привязывает `Panel:Bind()` без аргумента (`"Text"`, `"Value"`...) |
| `Route`, `Title`, `Layout`, `KeepAlive`, `Guard`, `Loader` | поля страниц, см. [Маршрутизация](#маршрутизация) |

Подсказки для редактора пишутся комментариями `---@class`:

```lua
---@class Card: Panel
---@field TitleLabel Label
local CARD = {}
```

### Жизненный цикл

1. `ui.Create` создаёт элемент и панель, подставляет поля из `свойств`.
2. Вызывается `Initialize` у всей цепочки классов (сначала база). Метод может ждать ответа сервера (см. ниже).
3. Применяются setter-свойства и добавляются дети из таблицы свойств.
4. Панель живёт, получает события.
5. `Remove()` удаляет панель: сначала удаляются дети, затем вызывается `OnRemove`, затем обратные вызовы из `CallOnRemove`, затем элемент убирается со страницы.

Дополнительно:

- `IsValid(панель)` (или `панель:IsValid()`) возвращает `true`, если панель существует и не удалена. Всегда проверяйте так панели, которые вы храните в переменных и используете позже.
- `Rebuild()` удаляет всех детей и снова запускает `Initialize`. Хуки, таймеры, привязки и ожидающие запросы, созданные прошлым `Initialize`, при этом отбрасываются.
- `Clear()` удаляет только детей.

### События

Все эти методы необязательны. Определите метод в классе или присвойте функцию полю у конкретной панели (`button.DoClick = function() ... end`), и он начнёт вызываться.

| Метод | Когда вызывается |
| --- | --- |
| `DoClick()` | клик левой кнопкой мыши. У отключённых панелей не вызывается. У `CheckBox` вместо него используйте `OnChange` |
| `DoRightClick()` | клик правой кнопкой. Если метод задан, контекстное меню браузера не показывается |
| `DoDoubleClick()` | двойной клик |
| `OnMousePressed(code)` | кнопка мыши нажата. `code` равен `MOUSE_LEFT` (1), `MOUSE_RIGHT` (2) или `MOUSE_MIDDLE` (3) |
| `OnMouseReleased(code)` | кнопка отпущена. Событие приходит той панели, на которой была нажата кнопка, даже если курсор ушёл |
| `OnCursorEntered()`, `OnCursorExited()` | курсор зашёл на панель или вышел с неё |
| `OnCursorMoved(x, y)` | курсор двигается над панелью; координаты внутри панели (в целых пикселях) |
| `OnFocusChanged(gained)` | панель или кто-то внутри неё получил (`true`) или потерял (`false`) фокус |
| `OnKeyCodePressed(key)` | нажата клавиша, пока в панели фокус. Верните `true`, чтобы отменить действие браузера по умолчанию |
| `Think()` | каждый кадр (около 60 раз в секунду). Назначайте только если нужна покадровая логика |
| `Paint(w, h)` | рисование на холсте, см. [Рисование](#рисование) |
| `PerformLayout(w, h)` | размер панели изменился или вызван `InvalidateLayout` |
| `OnRemove()` | панель удаляется |

Поля `Hovered` и `Depressed` (методы `IsHovered()` и `IsDown()`) показывают, что курсор сейчас над панелью или что на ней зажата кнопка.

Что нужно знать про мышь:

- Наведённой считается только самая верхняя панель под курсором.
- У `Label` и `Image` по умолчанию отключено реагирование на мышь, чтобы клики проходили к панели под ними. Если нужен `DoClick` или `OnCursorEntered` на надписи, вызовите `label:SetMouseInputEnabled(true)`. Кнопки, ссылки и поля реагируют на мышь всегда.
- Фокус клавиатуры получают кнопки, поля ввода и элементы со `SetAttr("tabindex", 0)`.
- Клик приходит только той панели, на которой он случился, и не «всплывает» к родителям. Если карточка с `DoClick` состоит из вложенных панелей, клик по вложенной панели до карточки не дойдёт. Вызовите у карточки `SetChildrenMouseInputEnabled(false)`: её дети (и те, что добавят позже) перестанут реагировать на мышь, и любой клик по карточке придёт в неё саму. Отдельный ребёнок может вернуть себе мышь через `SetMouseInputEnabled(true)`.

### Ожидание внутри обработчиков

Обработчики событий, `Initialize`, функции таймеров и хуков выполняются в корутинах Lua. Это позволяет писать запросы к серверу как обычные последовательные вызовы:

```lua
function BTN:DoClick()
    local user, err = http.Get("/api/users/1")
    if err then
        ui.Toast("Ошибка: " .. err.message)
        return
    end
    self:SetText(user.name)
end
```

Пока идёт запрос, страница не зависает: корутина просто приостановлена, а браузер занимается другими делами. Правила:

- Ожидающие функции (`http.Get`, `http.Post`, `Form:Submit`, `clipboard.ReadText`, `Request:Wait`...) работают только внутри обработчиков и `Initialize`. В других местах они выдадут ошибку `this call waits for a result...`. Там используйте вариант с обратным вызовом (`http.Fetch`).
- `Paint`, `PerformLayout`, `Think` и `OnRemove` выполняются синхронно и ждать не могут.
- Если панель удалили (или перестроили через `Rebuild`), пока её обработчик ждал, обработчик больше не продолжится. Поэтому страница, которая ждёт `http.Get` в `Initialize`, не будет трогать свои панели после ухода пользователя. Если панель была удалена, её запрос ещё и отменяется.
- Не вызывайте ожидающие функции внутри корутин, созданных вами через `coroutine.create`: ожидание рассчитано на корутину, которую запустил фреймворк.
- Пока корутина ждёт, могут прийти другие события. Например, пользователь нажмёт кнопку второй раз. Защищайтесь флагом или отключайте кнопку (`btn:SetEnabled(false)`).

### Хуки и таймеры панели

Хуки и таймеры, созданные через панель, автоматически снимаются при её удалении или перестройке, поэтому утечек не будет.

| Метод | Что делает |
| --- | --- |
| `Panel:Hook(событие, [имя], функция_или_имя_метода)` | как `hook.Add`, но живёт вместе с панелью. Если передать строку, будет вызван метод панели с таким именем. Один хук на пару «событие + имя» |
| `Panel:Unhook(событие, [имя])` | снять хук |
| `Panel:Timer(имя, задержка, повторы, функция_или_метод)` | как `timer.Create`. Задержка в секундах, `повторы` по умолчанию 1, `0` значит бесконечно |
| `Panel:TimerSimple(задержка, функция_или_метод)` | один вызов через время; не сработает, если панели уже нет |
| `Panel:RemoveTimer(имя)`, `Panel:TimerExists(имя)` | остановить таймер, проверить, что он идёт |
| `Panel:CallOnRemove(имя, функция)` | вызвать `функция(панель)` при удалении. Тот же `имя` заменяет прежнюю функцию |
| `Panel:RemoveCallOnRemove(имя)` | отменить такой вызов |

Глобальные `hook.Add` и `timer.Create` живут, пока вы их не снимете, поэтому внутри панелей используйте методы панели. Список событий для хуков в разделе [API браузера](#api-браузера).

```lua
function CLOCK:Initialize()
    self:Timer("tick", 1, 0, "UpdateTime")
    self:Hook("OnScreenSizeChanged", function(w, h) self:UpdateTime() end)
end
```

### Контекст: Provide и Inject

#### Зачем это нужно

Часто одно и то же значение нужно многим панелям на разной глубине: текущий пользователь, акцентный цвет, словарь переводов, настройки. Передавать его аргументом через каждый уровень (`Initialize` страницы, потом карточки, потом кнопки) неудобно, а глобальная переменная общая для всего приложения и не умеет сообщать об изменениях.

Контекст решает обе проблемы. Панель-предок публикует значение под ключом (`Provide`), а любая панель внутри неё забирает его (`Inject`), не зная, кто именно и на каком уровне его опубликовал. Это аналог контекста в React и `provide`/`inject` во Vue.

#### Методы

| Метод | Что делает |
| --- | --- |
| `panel:Provide(key, value)` | публикует `value` под ключом `key` для всех панелей внутри `panel` (детей, внуков и так далее) |
| `panel:Inject(key, default)` | возвращает значение от ближайшего предка, который опубликовал `key`. Если такого нет, возвращает `default` |
| `ui.Provide(key, value)` | публикует значение для всего приложения (то же, что `Provide` у корневой панели) |
| `ui.Inject(key, default)` | читает значение уровня приложения, минуя панели |
| `OnContextChanged(key, value)` | метод панели, который вызывается, когда предок опубликовал новое значение для ключа, прочитанного этой панелью |

Ключом может быть любое значение Lua. Обычно это строка (`"user"`, `"accent"`). Чтобы исключить случайные совпадения в большом проекте, используйте таблицу-ключ или префикс: `"myapp.user"`.

#### Как ищется значение

```text
Root                  ui.Provide("lang", "ru")
 └ AppLayout          Provide("user", me)
    └ Page
       ├ Card         Provide("accent", orange)
       │  └ Badge     Inject("accent") -> orange, Inject("user") -> me, Inject("lang") -> "ru"
       └ Badge        Inject("accent") -> nil (или значение по умолчанию)
```

- Поиск идёт вверх по дереву, начиная с родителя. Панель не видит то, что опубликовала сама: `Provide` у неё влияет только на потомков.
- Выигрывает ближайший предок. Вложенный `Provide` с тем же ключом перекрывает внешний, но только для своего поддерева.
- Корневая панель тоже предок, поэтому значения из `ui.Provide` видны через обычный `panel:Inject`. Дойдя до корня, поиск завершается и возвращает `default`.
- Предок, у которого значение равно `nil`, пропускается, поиск продолжается выше. Поэтому `panel:Provide(key, nil)` «снимает» значение для поддерева.

#### Пример: пользователь для всего приложения

Лейаут публикует состояние пользователя, а значок в шапке и любые страницы читают его.

```lua
local LAYOUT = {}

function LAYOUT:Initialize()
    local user = ui.State(nil)
    self:Provide("user", user)
    http.Fetch("/api/me", function(me) user:Set(me) end)

    local header = ui.Create("Row", self)
    header:Dock(DOCK_TOP)
    header:SetTall(54)
    ui.Create("UserBadge", header)

    local outlet = self:Add("Panel")
    outlet:Dock(DOCK_FILL)
    self:SetOutlet(outlet)
end

ui.Register("AppLayout", LAYOUT, "Panel")
```

```lua
local BADGE = {}

function BADGE:Initialize()
    local user = self:Inject("user")
    self:Bind("Text", function()
        local u = user and user:Get()
        return u and u.name or "Гость"
    end)
end

ui.Register("UserBadge", BADGE, "Label")
```

Здесь публикуется не сам объект пользователя, а `ui.State` с ним. Так панели следят за изменениями через привязку (`Bind`), а запрос `/api/me` можно выполнить уже после создания детей: когда ответ придёт, значок обновится сам.

#### Пример: перекрытие значения в поддереве

```lua
function PAGE:Initialize()
    self:Provide("accent", Color(92, 156, 255))

    local warning = ui.Create("Panel", self)
    warning:Provide("accent", Color(255, 160, 70))
    ui.Create("AccentBadge", warning)

    ui.Create("AccentBadge", self)
end
```

Первый значок внутри `warning` получит оранжевый цвет, второй (прямо в странице) синий. Класс `AccentBadge` не знает об этом и просто пишет `self:Inject("accent", Color(92, 156, 255))`.

#### Пример: реакция на изменение

Если предок позже опубликует новое значение под тем же ключом, у панелей, которые его прочитали, вызывается метод `OnContextChanged(key, value)`:

```lua
local BADGE = {}

function BADGE:Initialize()
    self:Apply(self:Inject("accent", Color(92, 156, 255)))
end

function BADGE:Apply(color)
    self:SetBackgroundColor(color)
end

function BADGE:OnContextChanged(key, color)
    self:Apply(color)
end

ui.Register("AccentBadge", BADGE, "Label")
```

```lua
page:Provide("accent", Color(80, 200, 140))
```

После этого вызова все `AccentBadge` под `page`, которые прочитали значение от этой страницы, перекрасятся. Вызов `Provide` с тем же значением (по `==`) ничего не делает.

Способ с `ui.State` из первого примера обычно проще: панель один раз подписывается через `Bind` или `Effect` и больше не нуждается в `OnContextChanged`. `OnContextChanged` удобен, когда значение нужно применить императивно (как в `Apply` выше).

#### Значения для всего приложения

`ui.Provide` можно вызывать в файле из `autorun/`: корневая панель создаётся до выполнения ваших файлов.

```lua
-- autorun/i18n.lua
ui.Provide("t", {
    save = "Сохранить",
    cancel = "Отмена",
})
```

```lua
function FORM:Initialize()
    local t = self:Inject("t")
    self:AddSubmit(t.save)
end
```

Если значение нужно в месте, где нет панели (обычная функция, хук), используйте `ui.Inject("t")`. Тот же приём годится для адреса API, текущего языка, настроек, которые не меняются в течение работы.

#### Подводные камни

- Публикуйте до создания детей. `Inject` выполняется в `Initialize` ребёнка, поэтому `Provide` нужно вызвать раньше. Если ребёнок уже прочитал значение и получил `default`, он ничего не узнает о более позднем `Provide`: подписка на изменения создаётся только тогда, когда значение действительно найдено у предка.
- Не публикуйте после ожидания. Если в `Initialize` лейаута сначала стоит `http.Get` (он приостанавливает метод), роутер успеет создать страницу раньше, чем выполнится `Provide`, а дети страницы прочитают `default`. Публикуйте в начале `Initialize`, а данные догружайте через `ui.State` и `http.Fetch`, как в примере выше. По той же причине лейаут не должен ждать ответа сервера до `SetOutlet`.
- Передавайте родителя при создании. Если панель читает `Inject` в `Initialize`, а создана как `ui.Create("X", nil, ...)` и только потом перенесена в родителя (например, через массив детей в таблице свойств), во время `Initialize` её предком была корневая панель, и она увидит только значения уровня приложения. Создавайте такую панель сразу с нужным родителем.
- Подписка привязана к тому предку, у которого значение было найдено в момент `Inject`. Если позже ближе к панели появится другой `Provide` с тем же ключом, уже прочитавшая панель продолжит следить за старым источником. Если нужно, пересоздайте панель (`Rebuild`).
- Изменение таблицы «на месте» не заметно. `Provide("settings", tbl)`, после чего вы меняете поля `tbl`: ссылка та же, `OnContextChanged` не вызовется. Публикуйте новую таблицу или кладите в контекст `ui.State` и вызывайте у него `Set` или `Notify`.
- `OnContextChanged` выполняется как обычный обработчик (в корутине): может ждать ответа сервера, ошибки в нём сообщаются, но не ломают страницу. Если панель к тому времени удалена, вызов отбрасывается.
- Контекст принадлежит дереву панелей, а не коду. Из `timer.Simple` или `http.Fetch` без панели `Inject` вызвать нельзя; пользуйтесь `ui.Inject` или читайте значение заранее в `Initialize` и сохраняйте в локальную переменную.

### Связь с родителем, детьми и слотами

| Метод | Что делает |
| --- | --- |
| `GetParent()`, `GetChildren()`, `GetChild(i)`, `ChildCount()` | навигация по дереву (индексы с 1) |
| `SetParent(родитель, [слот])` | перенести панель к другому родителю |
| `Remove()`, `Clear()` | удалить панель, удалить детей |
| `SetName(имя)`, `GetName()` | имя панели. Используется формами (`Form`, `ui.ApplyErrors`) и тестами. Без имени `GetName` возвращает имя класса |
| `SetSlot([имя], панель)`, `GetSlot([имя])` | задать или получить слот |
| `SetOutlet(панель)` | то же, что `SetSlot("outlet", панель)`, для лейаутов |

Слот это перенаправление: «всё, что создаётся внутри меня, кладётся не в меня, а в такую-то мою внутреннюю панель». Так сделана карточка из примера: у неё есть заголовок, тело и подвал, а пользователь карточки просто пишет `ui.Create("Label", card)`, и надпись попадает в тело.

```lua
function CARD:Initialize()
    self.Body = ui.Create("Column", self)
    self.Footer = ui.Create("Row", self)
    self:SetSlot(self.Body)
    self:SetSlot("footer", self.Footer)
end
```

- `ui.Create("Label", card)` положит надпись в `card.Body` (слот по умолчанию).
- `ui.Create("Button", card, { Slot = "footer" })` положит кнопку в `card.Footer`.
- `ui.Create("Label", card, { Slot = false })` положит надпись прямо в `card`, мимо слотов.
- Обращение к несуществующему именованному слоту это ошибка.

### Состояние и доступность панели

| Метод | Что делает |
| --- | --- |
| `SetVisible(b)`, `Show()`, `Hide()`, `IsVisible()` | показать или спрятать панель (спрятанная не занимает места) |
| `SetEnabled(b)`, `SetDisabled(b)`, `IsEnabled()`, `GetDisabled()` | включить или отключить. Отключённая панель не получает клики и выглядит полупрозрачной |
| `SetTooltip(текст)` | подсказка при наведении, браузер показывает её сам (атрибут `title`) |
| `SetRichTooltip(текст_или_функция)` | подсказка с содержимым из панелей: функция получает панель, в которую можно добавлять элементы |
| `RequestFocus()`, `KillFocus()`, `HasFocus()` | управление фокусом клавиатуры |
| `InvalidateLayout([сразу])` | вызвать `PerformLayout`; `true` значит немедленно |
| `InvalidateParent()`, `InvalidateChildren([рекурсивно])` | то же для родителя или детей |
| `InvalidatePaint()` | перерисовать `Paint` в этом кадре |
| `ScrollToChild(панель)` | прокрутить так, чтобы дочерняя панель была видна |
| `SetAttr`, `GetAttr`, `SetProp`, `GetProp`, `Invoke` | прямая работа с элементом, см. [Справочник по элементам](#справочник-по-элементам) |
| `SetError`, `GetError` | пометить панель ошибкой, см. [Формы и валидация](#формы-и-валидация) |

Методы раскладки и оформления (`SetSize`, `Dock`, `SetStyle`, `SetFont`...) описаны в следующем разделе.

## Раскладка и стили

### Как панели располагаются по умолчанию

Каждая панель это прямоугольник. Обычная панель (`Panel`, `Page`, `ScrollPanel`) раскладывает детей в столбец сверху вниз, и дети растягиваются на всю ширину родителя. Дети не сжимаются: если им не хватает места, содержимое выходит за границу родителя. Для длинного содержимого используйте `ScrollPanel`.

Есть три способа управлять расположением. Выбирайте по задаче, смешивать в одной панели разные способы для разных детей нужно осторожно.

| Способ | Когда использовать |
| --- | --- |
| `SetLayout` (ряд, столбец, сетка) | список элементов, форма, панель инструментов, галерея |
| `Dock` | каркас окна: шапка, боковая панель, подвал, основная область |
| `SetPos` | точное размещение по координатам (редко) |

### Размеры

Методы принимают число (пиксели) или строку с CSS-единицей (`"50%"`, `"fit-content"`, `"20em"`).

| Метод | Что делает |
| --- | --- |
| `SetSize(w, h)`, `SetWide(w)`, `SetTall(h)` | задать размер. `SetWidth` и `SetHeight` это синонимы. `nil` снимает ограничение |
| `SetMinSize(w, h)`, `SetMaxSize(w, h)` | минимальный и максимальный размер. `SetMaxSize(460)` ограничивает только ширину |
| `SizeToContents()`, `SizeToContentsX()`, `SizeToContentsY()` | размер по содержимому |
| `GetSize()`, `GetWide()`, `GetTall()` (`GetWidth`, `GetHeight`) | фактический размер в пикселях, как его посчитал браузер |
| `GetPos()`, `GetX()`, `GetY()` | положение относительно родителя |
| `GetScreenBounds()` | `x, y, w, h` в координатах окна браузера (та же система, что у `gui.MousePos`) |
| `LocalToScreen(x, y)`, `ScreenToLocal(x, y)` | пересчёт координат |
| `LocalCursorPos()` (синоним `CursorPos()`) | положение курсора внутри панели |

Если панель закрепена через `Dock`, часть размеров игнорируется (см. ниже).

### Ряд, столбец и сетка (flexbox и grid)

| Метод | Что делает |
| --- | --- |
| `SetLayout(mode)` | `LAYOUT_COLUMN` столбец, `LAYOUT_ROW` ряд, `LAYOUT_GRID` сетка. `nil` возвращает поведение по умолчанию. Готовые классы `Column`, `Row`, `Grid` включают режим сами |
| `SetGap(gap, [columnGap])` | промежуток между детьми. Второе число задаёт промежуток между столбцами, если он должен отличаться |
| `SetAlign(a)` | расположение по поперечной оси: `ALIGN_START`, `ALIGN_CENTER`, `ALIGN_END`, `ALIGN_STRETCH` (по умолчанию растянуть) |
| `SetJustify(j)` | расположение по главной оси: `JUSTIFY_START`, `JUSTIFY_CENTER`, `JUSTIFY_END`, `JUSTIFY_BETWEEN` (по краям, пустота между), `JUSTIFY_AROUND`, `JUSTIFY_EVENLY` |
| `SetAlignSelf(a)` | то же, что `SetAlign`, но для одного ребёнка: он сам выбирает своё место |
| `SetLayoutWrap(b)` | переносить детей на новую строку, если не помещаются (для ряда) |
| `SetGrow(n)` | доля свободного места, которую займёт ребёнок в ряду или столбце. Два ребёнка с `SetGrow(1)` делят место поровну, `SetGrow(2)` берёт вдвое больше |
| `SetColumns(cols)` | число равных столбцов (`SetColumns(3)`) или список ширин: числа это пиксели, строки это `"1fr"`, `"2fr"`, `"auto"`. Вызов включает режим сетки |

Без `SetColumns` сетка использует столько столбцов шириной от 160 пикселей, сколько помещается (`repeat(auto-fill, minmax(160px, 1fr))`).

```lua
local toolbar = ui.Create("Row", self, { Gap = 8, Align = ALIGN_CENTER })
ui.Create("Label", toolbar, { Text = "Поиск:" })
ui.Create("TextEntry", toolbar, { Grow = 1 })
ui.Create("Button", toolbar, { Text = "Найти" })
```

Здесь надпись и кнопка имеют свой размер, а поле занимает всё оставшееся место.

```lua
local gallery = ui.Create("Grid", self, { Gap = 12, Columns = 3 })
```

### Dock: каркас окна

`Dock` знаком по Garry's Mod: панель «приклеивается» к стороне родителя, а следующие панели делят то, что осталось.

| Константа | Значение |
| --- | --- |
| `DOCK_NONE` | не закреплена (по умолчанию) |
| `DOCK_TOP`, `DOCK_BOTTOM` | прижата к верху или низу, растянута на всю ширину; высоту задаёт `SetTall` |
| `DOCK_LEFT`, `DOCK_RIGHT` | прижата к левому или правому краю, растянута на всю высоту; ширину задаёт `SetWide` |
| `DOCK_FILL` | занимает всё оставшееся место; размеры игнорируются |

```lua
local header = ui.Create("Row", self)
header:Dock(DOCK_TOP)
header:SetTall(54)

local sidebar = ui.Create("Column", self)
sidebar:Dock(DOCK_LEFT)
sidebar:SetWide(220)

local content = ui.Create("Panel", self)
content:Dock(DOCK_FILL)
```

Важные правила:

- Порядок создания детей имеет значение, как в vgui: каждая закреплённая панель занимает свою сторону в той области, которая осталась свободной. Сначала создавайте верх и низ, затем боковые панели, последней `DOCK_FILL`.
- `DockMargin(l, t, r, b)` задаёт внешний отступ панели, `DockPadding(l, t, r, b)` внутренний (отступ от краёв до детей). Порядок: слева, сверху, справа, снизу.
- Под капотом `Dock` это одна CSS-сетка на родителе: каждая сторона добавляет строку или столбец. Если ни у одного ребёнка нет `Dock`, родитель работает как обычная панель.
- Панели без `Dock` и без `SetPos` в родителе с доками попадают в центральную ячейку, там же, где `DOCK_FILL`. Для стопки в центре заведите внутри `DOCK_FILL`-панели отдельный контейнер.
- Позиция `SetPos` игнорируется, пока панель закреплена.

### Абсолютное расположение

| Метод | Что делает |
| --- | --- |
| `SetPos(x, y)`, `SetX(x)`, `SetY(y)` | положение внутри родителя в пикселях или с единицами (`"50%"`). Игнорируется при `Dock` |
| `Center()` | по центру родителя |
| `SetZPos(z)` | порядок наложения: у кого больше, тот выше |

Каждая панель служит точкой отсчёта для детей с `SetPos`. Окна `Frame` и меню `Menu` располагаются относительно окна браузера.

### Цвета, прозрачность, текст

| Метод | Что делает |
| --- | --- |
| `SetBackgroundColor(c)`, `GetBackgroundColor()` | цвет фона: `Color` или строка CSS, например `ui.Var("surface")` (строка проверяется как в `SetStyle`); `nil` возвращает стандартный |
| `SetPaintBackground(b)` | `false` убирает фон полностью |
| `SetTextColor(c)`, `GetTextColor()` | цвет текста, принимает то же, что `SetBackgroundColor` |
| `SetAlpha(a)`, `GetAlpha()` | непрозрачность всей панели вместе с детьми, число 0..255 |
| `SetFont(name)`, `GetFont()` | шрифт по имени из `surface.CreateFont` |
| `SetContentAlignment(n)` | расположение текста внутри надписи по цифровой клавиатуре: 7 8 9 сверху, 4 5 6 посередине, 1 2 3 снизу. `5` это центр |
| `SetCursor(name)` | вид указателя мыши над панелью |
| `SetMouseInputEnabled(b)` | `false` делает панель прозрачной для мыши: клики проходят к панели под ней |

Имена курсоров: `"arrow"`, `"hand"` (ладонь), `"beam"` (текстовый), `"sizeall"`, `"sizewe"`, `"sizens"`, `"sizenesw"`, `"sizenwse"`, `"no"` (запрещено), `"waiting"` (часы), `"crosshair"`, `"blank"` (скрыт). Любая другая строка передаётся как есть и считается именем CSS-курсора (`"grab"`, `"not-allowed"`).

### SetStyle: любое CSS-свойство

`panel:SetStyle(свойство, значение)` или `panel:SetStyle({ свойство = значение, ... })`. Это окно в CSS для всего, для чего нет специального метода. Значение `nil` убирает свойство.

```lua
panel:SetStyle("border-radius", 8)
panel:SetStyle("borderRadius", 8)
panel:SetStyle({ radius = 8, color = Color(255, 255, 255), cursor = "pointer" })
```

Как значение Lua превращается в CSS:

| Значение | Результат |
| --- | --- |
| число | пиксели (`8` это `8px`). Исключения без единиц: `opacity`, `z-index`, `font-weight`, `line-height`, `flex`, `flex-grow`, `flex-shrink`, `order`, `scale`, `aspect-ratio`. Для `rotate` число это градусы |
| `Color` | `rgba(...)` |
| строка | как есть, после проверки (см. ниже) |
| `false` | `none` |

Разрешённые свойства: фон (`background`, `background-color`, `background-image`, `background-position`, `background-size`, `background-repeat`), `color`, `opacity`, `visibility`, `cursor`; рамки (`border`, `border-width/style/color` и варианты `-top/-right/-bottom/-left`), радиусы (`border-radius` и угловые), `outline` и его части; `box-shadow`, `text-shadow`, `filter`, `backdrop-filter`, `mix-blend-mode`; `transform`, `transform-origin`, `translate`, `rotate`, `scale`, `transition`; `overflow`, `overflow-x`, `overflow-y`, `text-overflow`; отступы `padding*` и `margin*`; размеры (`width`, `height`, `min-*`, `max-*`, `aspect-ratio`); `gap`, `row-gap`, `column-gap`, `flex`, `flex-grow`, `flex-shrink`, `flex-basis`, `order`, `align-self`, `justify-self`, `z-index`; шрифт и текст (`font-size`, `font-weight`, `font-style`, `font-family`, `letter-spacing`, `line-height`, `word-spacing`, `font-variant-numeric`, `font-feature-settings`, `font-variation-settings`, `font-optical-sizing`, `text-align`, `text-decoration`, `text-transform`, `text-indent`, `white-space`, `word-break`, `overflow-wrap`); `user-select`, `pointer-events`, `object-fit`, `object-position`; `caret-color` (цвет курсора в поле ввода), `accent-color` (цвет встроенных флажков и ползунков), `scrollbar-width` и `scrollbar-color` (толщина и цвет полос прокрутки этой панели).

Цифры одинаковой ширины, чтобы числа в колонках не «прыгали», включаются так: `SetStyle("fontVariantNumeric", "tabular-nums")`. Возможности шрифта задаются строкой с кавычками: `SetStyle("fontFeatureSettings", '"tnum" 1, "cv11" 1')`.

Расположение (`position`, `display`, `left`, `top`, `grid-*`) намеренно исключено: им управляют `SetPos`, `Dock` и `SetLayout`. Свойство не из списка вызывает ошибку `style property '...' is not allowed`.

Строковые значения проверяются: в них нельзя использовать символы `\ ; { } < >` и любые CSS-функции, кроме безопасных (`rgb`, `rgba`, `hsl`, `calc`, `min`, `max`, `clamp`, `var`, `linear-gradient`, `radial-gradient`, `conic-gradient`, `translate`, `rotate`, `scale`, `skew`, `matrix`, `cubic-bezier`, `steps`, `blur`, `brightness`, `contrast`, `drop-shadow`, `grayscale`, `hue-rotate`, `invert`, `saturate`, `sepia`, `minmax`, `fit-content`, `repeat` и родственные). `url()` запрещена: значение стиля не должно заставлять браузер что-то скачивать. Картинки показывайте элементом `Image`.

Кроме обычных CSS-имён принимаются сокращения фреймворка:

| Ключ | Пример значения |
| --- | --- |
| `background` | `Color(...)` или строка (`"linear-gradient(...)"`) |
| `textColor` | `Color(...)` (то же, что `color`) |
| `alpha` | `0..255` (вместо `opacity`) |
| `border` | число (ширина), `Color`, `false`, строка или таблица `{ ширина, цвет, стиль }` |
| `radius` | число или таблица из четырёх чисел: верхний левый, верхний правый, нижний правый, нижний левый |
| `shadow` | таблица `{ x, y, blur, color, spread }` или список таких таблиц, `false` |
| `gradient` | см. `SetGradient` |
| `transform` | таблица `{ x, y, rotate, scale, scaleX, scaleY, skewX, skewY }` |
| `overflow` | `"hidden"`, `"auto"`... или `{ x, y }` |
| `padding`, `margin` | число, строка или таблица `{ слева, сверху, справа, снизу }` |
| `font` | имя шрифта из `surface.CreateFont` |

### Готовые методы оформления

| Метод | Что делает |
| --- | --- |
| `SetBorder(width, [color], [style])` | рамка. `style` это `"solid"` (по умолчанию), `"dashed"`, `"dotted"`, `"double"` и т. д. Цвет по умолчанию берётся из темы. `SetBorder(false)` убирает рамку, `SetBorder(nil)` возвращает стандартную |
| `SetRadius(r, [tr], [br], [bl])` | скругление углов; с одним аргументом для всех, с четырьмя по углам |
| `SetShadow(x, y, [blur], [color], [spread], [inset])` | тень. Можно передать таблицу или список таблиц; `inset` рисует тень внутри. `false` убирает |
| `SetGradient(from, to, [angle])` | градиент между двумя цветами. Угол в градусах: 180 (по умолчанию) сверху вниз, 90 слева направо. Таблица `{ c1, c2, { c3, 80 }, angle = 90, radial = false }` позволяет несколько остановок (число рядом с цветом это процент) и радиальный градиент |
| `SetTransform(t)` | сдвиг, поворот, масштаб, наклон. Не влияет на соседей и не зависит от `SetPos` |
| `SetOverflow(x, [y])` | что делать с лишним содержимым: `"visible"`, `"hidden"`, `"scroll"`, `"auto"`, `"clip"` |
| `SetTransition(duration, [ease])` | плавно анимировать каждое изменение стиля за `duration` секунд. `ease`: `"ease"`, `"linear"`, `"ease-in-out"`, `"cubic-bezier(...)"`. `nil` выключает |

```lua
ui.Create("Button", row, {
    Text = "Градиент",
    Border = false,
    Radius = 10,
    Gradient = { Color(92, 156, 255), Color(170, 90, 255), 135 },
    Shadow = { 0, 4, 12, Color(0, 0, 0, 90) },
    Transition = 0.2,
})
```

### Стили для состояний

`SetStyleHover(стили)`, `SetStyleActive(стили)`, `SetStyleFocus(стили)`, `SetStyleDisabled(стили)` (общая форма `SetStyleState(состояние, стили)`) задают оформление для состояний: курсор над панелью, кнопка мыши зажата, фокус на панели или внутри неё, панель отключена. Принимают те же ключи, что `SetStyle`. `nil` или пустая таблица снимает стиль.

Стили состояний превращаются в правила таблицы стилей CSS, поэтому браузер переключает их сам и Lua на наведении не вызывается. Правила помечены как приоритетные (`!important`), чтобы перебить прямые стили вроде `SetBackgroundColor`, пока состояние активно.

```lua
ui.Create("Button", row, {
    Text = "Наведи и нажми",
    Transition = 0.15,
    StyleHover = { background = Color(92, 156, 255), transform = { y = -2 } },
    StyleActive = { transform = { scale = 0.96 } },
})
```

### Анимации

| Метод | Что делает |
| --- | --- |
| `AlphaTo(alpha, duration, [delay], [callback])` | плавно изменить непрозрачность |
| `MoveTo(x, y, duration, [delay], [ease], [callback])` | плавно переместить панель (переводит её в абсолютное расположение) |
| `SizeTo(w, h, duration, [delay], [ease], [callback])` | плавно изменить размер |

Время и задержка в секундах. `callback(панель)` вызывается, когда анимация должна закончиться. Параметр `ease` принимается для совместимости с Garry's Mod и не используется.

### Шрифты

Шрифт задаётся именем. Встроенные: `"Default"` (14 пикселей), `"DefaultBold"` (14, жирный), `"Small"` (12), `"Large"` (20), `"Title"` (28, жирный).

| Функция | Что делает |
| --- | --- |
| `surface.CreateFont(name, data)` | зарегистрировать шрифт. `data`: `font` (семейство, например `"Roboto"`), `size` (пиксели, по умолчанию 14), `weight` (толщина, по умолчанию 400, жирный 700), `italic`, `url` (файл шрифта) |
| `surface.LoadFont(family, url, [data])` | скачать файл шрифта (`woff2`, `ttf`) и зарегистрировать под именем семейства. `data`: `weight`, `italic` |
| `surface.IsFontLoaded(family)` | файл скачан? Хук `OnFontLoaded` срабатывает один раз, поэтому при создании панели проверяйте этим методом |

```lua
surface.CreateFont("Big", {
    font = "Source Serif 4", size = 36, weight = 700,
    url = "/fonts/SourceSerif4-Bold.woff2",
})
```

Пока файл скачивается, текст показывается запасным системным шрифтом, затем заменяется сам. Файлы шрифтов кладите в папку для статических файлов (`App::public`): по умолчанию политика безопасности разрешает загрузку только с вашего сайта.

### Тема оформления

`ui.SetSkin(таблица)` меняет цвета и скругление всех встроенных элементов. Под капотом это CSS-переменные.

| Ключ | Что красит | Значение по умолчанию |
| --- | --- | --- |
| `background` | фон страницы | `#1b1d21` |
| `text` | основной текст | `#e4e6eb` |
| `textMuted` | приглушённый текст, подсказки | `#9aa0aa` |
| `panel` | фон окон, меню, всплывающих слоёв | `#25282d` |
| `accent` | акцент: фокус, ссылки, выбранные пункты | `#4c8dff` |
| `danger` | ошибки | `#ff6b6b` |
| `border` | рамки | `#3a3f47` |
| `input` | фон полей ввода | `#15171a` |
| `button`, `buttonHover` | кнопки и их наведение | `#33373e`, `#3d424a` |
| `radius` | скругление, число в пикселях | `6` |
| `success` | успех: значки, статус «в сети», полосы | `#3ddc97` |
| `warning` | предупреждение | `#ff9f43` |
| `onAccent` | текст на акцентном фоне (главные кнопки, выбранный день) | `#ffffff` |

Значением может быть `Color`, число (для `radius`, в пикселях) или строка CSS (`"#fff"`). Строка проверяется так же, как значение `SetStyle`: `url()`, `;` и другие запрещённые конструкции вызывают ошибку. Неизвестный ключ тоже вызывает ошибку. Тема по умолчанию тёмная. Вызывать `ui.SetSkin` удобно в файле из `autorun/`, но можно и в любой момент работы: изменения применяются сразу.

`ui.GetSkin(key)` возвращает то, что для ключа последним передали в `ui.SetSkin` (`Color`, число или строку), или `nil`, пока действует значение по умолчанию.

### Свои переменные темы

Набора `ui.SetSkin` хватает встроенным элементам, но у приложения обычно своя палитра: несколько ступеней фона, смысловые цвета, цвета графиков. Если раздать панелям готовые `Color`, то при смене темы каждую панель придётся перекрашивать вручную или пересоздавать страницу. Вместо этого объявите свои CSS-переменные и ссылайтесь на них. Смена темы тогда сводится к одному вызову, а браузер перекрасит всё сам, без перестройки страницы.

| Функция | Что делает |
| --- | --- |
| `ui.SetVars(t)` | объявить или изменить переменные: `{ имя = значение }`. Значение: `Color`, число (пиксели) или строка CSS (проверяется как в `SetStyle`). `false` удаляет переменную. В браузере переменная называется `--app-<имя>` |
| `ui.Var(name)` | строка `"var(--app-<имя>)"` для `SetStyle`, `SetBackgroundColor`, `SetTextColor`, стилей состояний (`SetStyleHover`...), градиентов и рамок |
| `ui.GetVar(name, [default])` | значение, переданное в `ui.SetVars` (`Color` остаётся `Color`), или `default` |

Имя состоит из латинских букв, цифр и дефиса и начинается с буквы: `surface2`, `line-strong`, `series1`.

```lua
-- autorun/theme.lua
local THEMES = {
    graphite = { bg = Color(19, 20, 23), surface = Color(29, 31, 36), text = Color(236, 237, 240), accent = Color(245, 166, 35) },
    porcelain = { bg = Color(244, 245, 247), surface = Color(255, 255, 255), text = Color(24, 28, 38), accent = Color(184, 110, 0) },
}

function SetTheme(name)
    ui.SetVars(THEMES[name])
    storage.Set("theme", name)
end

SetTheme(storage.Get("theme") or (browser.ColorScheme() == "light" and "porcelain" or "graphite"))
```

```lua
card:SetBackgroundColor(ui.Var("surface"))
title:SetTextColor(ui.Var("text"))
button:SetStyleHover({ background = ui.Var("accent") })
```

Холсты (`Paint`) не следят за CSS-переменными, поэтому рисуйте цветом из `ui.GetVar`: `draw.RoundedBox(8, 0, 0, w, h, ui.GetVar("surface"))`. После каждого `ui.SetVars` и `ui.SetSkin` все панели с `Paint` перерисовываются сами, а затем срабатывает хук `OnSkinChanged`. Чтобы `Paint` получил `Color`, передавайте в `ui.SetVars` именно `Color`, а не строку.

### Размер окна и адаптивность

- `ScrW()` и `ScrH()` возвращают размеры окна браузера в пикселях. Хук `OnScreenSizeChanged(w, h)` срабатывает при изменении размера.
- Для адаптивной вёрстки используйте проценты, `SetLayoutWrap(true)`, сетку с `repeat(auto-fill...)` по умолчанию и `SetMaxSize`. Если нужно перестроить интерфейс под ширину, повесьте хук `OnScreenSizeChanged` и вызовите `Rebuild()` у страницы.
- Тёмная или светлая тема системы определяется через `browser.ColorScheme()`, см. [API браузера](#api-браузера).

## Справочник по элементам

Все элементы наследуют методы `Panel` (см. разделы выше). Ниже перечислено то, что добавляет каждый класс. Свойства при создании передаются так же, как всегда: `ui.Create("Slider", parent, { Min = 0, Max = 10 })`. Элементы, у которых есть `BindDefault`, можно привязать к состоянию (`Bind`), см. [Реактивное состояние](#реактивное-состояние).

### Label

Надпись. HTML: `<span>`. По умолчанию не реагирует на мышь.

| Метод | Описание |
| --- | --- |
| `SetText(text)`, `GetText()` | текст. Любое значение превращается в строку, `nil` в пустую. Текст выводится как текст, а не как HTML, поэтому пользовательские данные безопасны |
| `SetWrap(b)` | переносить длинный текст по словам. По умолчанию строки не переносятся, а символы перевода строки сохраняются |

`BindDefault` равен `"Text"`.

### Button

Кнопка, наследник `Label`. HTML: `<button>`. Событие `DoClick`. Отключённая кнопка (`SetEnabled(false)`) не нажимается.

### TextEntry

Поле ввода. HTML: `<input>` или `<textarea>` внутри `<div>`.

| Метод | Описание |
| --- | --- |
| `SetValue(v)`, `GetValue()` | текст поля (`GetValue` никогда не возвращает `nil`). `SetText` и `GetText` это синонимы |
| `GetInt()`, `GetFloat()` | значение как число или `nil`, если это не число |
| `SetPlaceholderText(text)` | серая подсказка внутри пустого поля |
| `SetMaxLength(n)` | максимальное число символов |
| `SetEditable(b)` | `false` делает поле только для чтения |
| `SetMultiline(b)` | `true` превращает поле в многострочное (`<textarea>`) |
| `SetInputType(t)` | `"text"`, `"password"` (скрытые символы), `"email"`, `"number"`, `"search"`, `"tel"`, `"url"`. Мобильные браузеры покажут подходящую клавиатуру |
| `SetNumeric(b)` | сокращение для `SetInputType("number")` |

События:

| Метод | Когда |
| --- | --- |
| `OnChange(self)` | после каждого изменения текста |
| `OnValueChange(self, value)` | то же, но с новым значением |
| `OnEnter(self, value)` | нажат Enter (в однострочном поле) |

`BindDefault` равен `"Value"`; привязка к `ui.State` двусторонняя. Для поля с `InputType = "number"` форма `Form` отдаёт значение числом.

### CheckBox

Флажок с подписью, наследник `Label`. HTML: `<label>` с `<input type="checkbox">`. Подпись задаётся `SetText` (или `Text = "..."`).

| Метод | Описание |
| --- | --- |
| `SetChecked(b)`, `GetChecked()` | состояние. `SetValue` и `GetValue` это синонимы |
| `Toggle()` | переключить, вызвав `OnChange` |

Событие: `OnChange(self, checked)`. Используйте его вместо `DoClick`. `BindDefault` равен `"Checked"`.

### ComboBox

Выпадающий список. HTML: `<select>`. Позиции считаются с единицы.

| Метод | Описание |
| --- | --- |
| `AddChoice(text, [data], [select])` | добавить пункт; `data` это любое значение, привязанное к пункту; `select = true` выбирает его. Возвращает номер пункта |
| `Clear()` | удалить все пункты |
| `ChooseOptionID(i)`, `ChooseOption(text)` | выбрать пункт по номеру или тексту (`SetValue` синоним `ChooseOption`) |
| `GetSelectedID()` | номер выбранного пункта или `nil` |
| `GetSelected()` | `text, data` выбранного пункта |
| `GetValue()` | текст выбранного пункта |
| `GetOptionText(i)`, `GetOptionData(i)` | текст и данные пункта по номеру |

Событие: `OnSelect(self, index, text, data)` срабатывает, когда выбор сделал пользователь (а не код). `BindDefault` равен `"Value"`.

### Slider и NumberWang

`Slider` это ползунок (`<input type="range">`), `NumberWang` числовое поле со стрелками (`<input type="number">`). Методы одинаковые.

| Метод | Описание |
| --- | --- |
| `SetMin(v)`, `SetMax(v)`, `SetMinMax(lo, hi)`, `GetMin()`, `GetMax()` | диапазон. У `Slider` по умолчанию 0..100 |
| `SetDecimals(n)` | число знаков после запятой, задаёт шаг (`0` шаг 1, `2` шаг 0.01) |
| `SetValue(v)`, `GetValue()` | значение (число) |

Событие: `OnValueChanged(self, value)`. `BindDefault` равен `"Value"`.

### ProgressBar

Полоса прогресса. HTML: `<progress>`. `SetFraction(f)` принимает число от 0 до 1 (значения за пределами обрезаются), `GetFraction()` возвращает его. `BindDefault` равен `"Fraction"`.

### Image

Картинка. HTML: `<img>`.

| Метод | Описание |
| --- | --- |
| `SetImage(url)`, `GetImage()` | адрес. Допустимы `http`, `https`, `data`, `blob` и относительные адреса; остальное отклоняется ошибкой `blocked URL` |
| `SetAltText(text)` | альтернативный текст для скринридеров и для случая, когда картинка не загрузилась |
| `SetKeepAspect(b)` | вписать картинку в панель, сохранив пропорции |

По умолчанию заголовок безопасности разрешает картинки только с вашего сайта, из `data:` и `blob:`. Для картинок с других сайтов нужно расширить политику, см. [Безопасность](#безопасность).

### Link

Ссылка, наследник `Label`. HTML: `<a>`.

| Метод | Описание |
| --- | --- |
| `SetURL(url)` | адрес. Принимаются `http`, `https`, `mailto` и относительные адреса. Остальные (`javascript:`, `data:`) отклоняются: ссылка остаётся без адреса, об этом сообщается как об ошибке, а метод возвращает `false`. Иначе `true` |
| `GetURL()` | текущий адрес |
| `SetNewTab(b)` | открывать в новой вкладке (с защитой `noopener`) |

Клик по ссылке внутри вашего сайта (адрес начинается с одного `/`) идёт через роутер, без перезагрузки страницы. Клик с зажатыми Ctrl, Shift, Alt, Meta или средней кнопкой остаётся за браузером (откроет новую вкладку). Ссылки на другие сайты открываются обычным образом. `DoClick` вызывается перед переходом.

### ScrollPanel

Прокручиваемая область. HTML: `<div>` с полосами прокрутки. Прокрутка появляется, когда содержимое выше панели, поэтому панели нужна ограниченная высота (`Dock`, `SetTall`, `SetGrow`). `AddItem(panel)` переносит панель внутрь, `GetCanvas()` возвращает саму панель.

### Row, Column, Grid

Контейнеры с готовым режимом раскладки (`LAYOUT_ROW`, `LAYOUT_COLUMN`, `LAYOUT_GRID`).

### Page

Страница, привязанная к адресу. HTML: `<main>`. Методы `SetTitle(title)` и `GetTitle()` меняют заголовок вкладки. Поля и правила описаны в разделе [Маршрутизация](#маршрутизация).

### Frame

Окно. HTML: `<dialog>`. Создаётся по центру размером 420 на 300. Дети панели появляются внутри окна под шапкой. Шапка с заголовком и кнопкой закрытия создаётся автоматически, окно можно перетаскивать за шапку.

| Метод | Описание |
| --- | --- |
| `SetTitle(text)`, `GetTitle()` | заголовок |
| `ShowCloseButton(b)` | показать или скрыть кнопку закрытия |
| `SetDraggable(b)`, `GetDraggable()` | можно ли перетаскивать |
| `SetSizable(b)` | позволить менять размер за правый нижний угол |
| `SetBackgroundBlur(b)` | размывать страницу за модальным окном |
| `SetDeleteOnClose(b)` | при закрытии удалять окно (по умолчанию `true`) или только прятать |
| `MakePopup()` | сделать окно модальным: страница под ним затемняется и блокируется, фокус остаётся в окне, Esc закрывает |
| `IsModal()` | модальное ли |
| `Close()` | закрыть; вызывает `OnClose` |

Поля: `Header`, `TitleLabel`, `CloseButton`. Событие: `OnClose(self)`. Без `MakePopup` окно не модальное: страница под ним продолжает работать.

```lua
local frame = ui.Create("Frame")
frame:SetTitle("Подтверждение")
frame:SetSize(340, 170)
frame:MakePopup()
ui.Create("Label", frame, { Text = "Удалить всё?" })
```

### Menu и MenuOption

Всплывающее меню. HTML: Popover API, меню само закрывается при клике вне его и по Esc.

```lua
local menu = ui.Menu()
menu:AddOption("Копировать", function() ui.Toast("Скопировано") end)
menu:AddOption("Вставить"):SetEnabled(false)
menu:AddSpacer()
local sub = menu:AddSubMenu("Цвет")
sub:AddOption("Синий", function() end)
menu:Open()
```

| Метод | Описание |
| --- | --- |
| `ui.Menu([parent])` | создать меню (то же, что `ui.Create("Menu", parent)`) |
| `AddOption(text, [fn])` | добавить пункт, `fn(option)` вызывается при выборе. Возвращает `MenuOption` (у него работают `SetEnabled`, `SetText`, `DoClick`) |
| `AddSpacer()` | разделительная линия |
| `AddSubMenu(text, [fn])` | пункт с вложенным меню. Возвращает подменю и пункт |
| `Open([x, y])` | показать в точке с координатами окна браузера, по умолчанию у курсора. Меню остаётся внутри окна. Если открыто модальное окно, меню переносится в него |
| `Hide()`, `CloseAll()` | закрыть это меню; закрыть меню вместе с родительскими |
| `IsOpen()` | открыто ли |
| `SetDeleteSelf(b)` | удалять меню после закрытия (по умолчанию `true`, как одноразовое меню в Garry's Mod) |

Типичное применение: `DoRightClick` панели строит и открывает меню.

В меню кладутся только пункты, разделители и подменю. Для своего содержимого (календарь, список флажков, форма) используйте `Popover`.

### Popover

Всплывающий слой с любыми панелями внутри. Как и `Menu`, он показывается в верхнем слое страницы (Popover API) поверх всего, включая родителей с `overflow: hidden`, и сам закрывается по Esc и по клику вне него. Располагается рядом с панелью-якорем, а если места не хватает, переходит на другую сторону и не выходит за край окна.

```lua
local button = ui.Create("Button", row, { Text = "Выбрать день" })
local pop = ui.Create("Popover", row)
local days = ui.Create("Grid", pop, { Columns = 7, Gap = 4 })
for d = 1, 30 do
    ui.Create("Button", days, { Text = d, DoClick = function()
        picked:SetText("День " .. d)
        pop:Hide()
    end })
end
button.DoClick = function() pop:Toggle(button) end
```

| Метод | Описание |
| --- | --- |
| `Open(anchor)` | показать рядом с панелью `anchor` |
| `Open([x, y])` | показать в точке с координатами окна, по умолчанию у курсора |
| `Toggle(anchor)` | открыть рядом с якорем или закрыть, если открыт. Вызывайте из `DoClick` якоря (см. ниже) |
| `Hide()` | закрыть |
| `IsOpen()`, `GetAnchor()` | открыт ли; текущий якорь |
| `SetSide(side)` | сторона от якоря: `"bottom"` (по умолчанию), `"top"`, `"left"`, `"right"` |
| `SetAlign(align)` | выравнивание вдоль якоря: `"start"` (по умолчанию), `"center"`, `"end"` |
| `SetGap(px)` | расстояние до якоря, по умолчанию 6 |
| `SetMatchAnchorWidth(b)` | не уже якоря: удобно для выпадающих списков |
| `SetAutoClose(b)` | `false`: Esc и клик снаружи не закрывают, только `Hide()` |
| `SetDeleteSelf(b)` | `true`: удалить после закрытия. По умолчанию popover сохраняется и открывается повторно |

События: `OnOpen(self)` и `OnClose(self)`. `OnClose` вызывается один раз при любом закрытии: `Hide`, Esc, клик снаружи.

Что нужно знать:

- Создавайте popover с родителем на странице (обычно рядом с якорем), тогда он удалится вместе со страницей. Сам по себе он не занимает места в раскладке родителя.
- По умолчанию у popover отступ 8 пикселей, фон, рамка и тень из темы. Их можно поменять как у любой панели (`DockPadding`, `SetStyle`), раскладка внутри по умолчанию столбцом.
- Клик снаружи закрывает popover в момент отпускания кнопки мыши, перед `DoClick` якоря. Если в `DoClick` написать `Open`, клик по якорю закроет popover и сразу откроет его снова. `Toggle` в течение 0,3 секунды после такого закрытия пропускает клик по тому же якорю, поэтому кнопка открывает и закрывает popover как ожидается.
- Если открыто модальное окно, popover переносится в него, иначе он был бы недоступен для мыши.
- Вложенный popover или меню, открытое из popover, создавайте с родителем внутри внешнего popover: иначе открытие второго закроет первый.
- При изменении размера окна открытый popover пересчитывает положение.

### Tabs

Вкладки. Кнопки переключаются мышью и клавишами стрелок, Home и End (с учётом доступности).

| Метод | Описание |
| --- | --- |
| `AddTab(title)` | создать вкладку, вернуть панель с её содержимым. Первая вкладка выбирается автоматически |
| `Select(index)` | выбрать вкладку (с единицы) |

Событие: `OnSelect(self, index, body)`.

### DataGrid (Table)

Таблица с виртуальной прокруткой: в браузере существуют только видимые строки, поэтому тысячи записей не тормозят. `Table` это синоним.

```lua
local grid = self:Add("DataGrid", { Dock = DOCK_FILL })
grid:SetColumns({
    { key = "id", title = "№", width = 80 },
    { key = "label", title = "Название" },
})
grid:SetDataSource(function(offset, limit)
    return http.Get(("/api/rows?offset=%d&limit=%d"):format(offset, limit))
end, 64)
```

| Метод | Описание |
| --- | --- |
| `SetColumns(columns)` | колонки: `key` (поле в строке), `title`, `width` (число в пикселях или строка вроде `"1fr"`; по умолчанию равные доли), `format(value, row, index)` возвращает текст ячейки |
| `SetRows(rows)` | показать готовый список строк |
| `SetDataSource(loader, [pageSize])` | подгружать данные порциями по мере прокрутки. `loader(offset, limit)` может ждать `http.Get`. Он должен вернуть `{ total = N, rows = {...} }` с ровно `min(limit, total - offset)` строками, либо `nil, ошибка`. Смещение считается с нуля. Размер порции по умолчанию 64 |
| `SetRowHeight(px)` | высота строки (по умолчанию 32) |
| `Retry()` | повторить порции, которые не загрузились |

Событие: `OnLoadError(self, message, offset)`. При ошибке под таблицей появляется кнопка повторной загрузки. Одновременно выполняются не более двух запросов. Таблице нужна высота (по умолчанию 256 пикселей): задайте `Dock = DOCK_FILL`, `SetTall` или `SetGrow`.

### Disclosure

Раскрывающийся блок. Поля `Toggle` (кнопка-заголовок) и `Body` (панель с содержимым, создавайте детей в ней). `SetText(text)` меняет заголовок, `SetExpanded(b)` раскрывает или сворачивает. По умолчанию свёрнут.

### Tree и TreeNode

Дерево. `tree:AddNode(label, data)` создаёт корневой узел, `node:AddNode(label, data)` дочерний. `node:Select()` выбирает узел программно. У `TreeNode` (наследник `Disclosure`) поля `Toggle` и `Body`. Событие: `tree.OnSelect(self, node, data)`.

### Dropdown

Кнопка с выпадающим меню (наследник `Button`). `AddOption(text, data)` добавляет пункт. После выбора текст кнопки меняется на выбранный пункт. Событие: `OnSelect(self, index, data)`. В отличие от `ComboBox` меню строится из панелей и выглядит одинаково во всех браузерах.

### FileInput

Выбор файлов. HTML: `<input type="file">`.

| Метод | Описание |
| --- | --- |
| `SetAccept(types)` | какие файлы предлагать: `"image/*"`, `".pdf,.docx"` |
| `SetMultiple(b)` | можно выбрать несколько |
| `GetFiles()` | список выбранных `{ name, size, type }` (размер в байтах, `type` это MIME-тип) |
| `Clear()` | сбросить выбор |

Событие: `OnChange(self, files)`. Отправить выбранное на сервер можно через `http.Upload(url, input)`, см. [HTTP и данные](#http-и-данные). Содержимое файла в Lua не читается.

### Form

Форма с полями, подписями, ошибками и отправкой на сервер, см. [Формы и валидация](#формы-и-валидация).

### Уведомления и подтверждение

| Функция | Что делает |
| --- | --- |
| `ui.Toast(message, [seconds], [kind])` | краткое уведомление в правом нижнем углу, исчезает через `seconds` секунд (по умолчанию 4). `kind` (`"info"`, `"success"`, `"warning"`, `"danger"`) добавляет цветную полосу слева. Возвращает надпись. Скринридеры озвучивают его (`aria-live`) |
| `ui.Confirm(message, callback, [title], [parent])` | модальное окно `Dialog` с кнопками подтверждения и отмены. `callback(accepted)` получает `true` для подтверждения и `false` для отмены, Esc и кнопки закрытия |

```lua
ui.Confirm("Удалить сохранённую тему?", function(ok)
    if ok then cookie.Remove("theme") end
end, "Тема")
```

Вместо строки можно передать таблицу настроек:

| Ключ | Что задаёт |
| --- | --- |
| `Message` | текст вопроса |
| `Build(body)` | функция, которая сама наполняет тело окна панелями (например, текст с выделенными словами) |
| `Title` | заголовок |
| `Accept`, `Cancel` | надписи кнопок |
| `AcceptVariant`, `CancelVariant` | вид кнопок (`SetVariant`), по умолчанию `"primary"` и `"outline"` |
| `Width` | ширина окна в пикселях |

```lua
ui.Confirm({
    Title = "Завершить смену", Accept = "Да", Cancel = "Нет", CancelVariant = "danger",
    Build = function(body)
        body:Add("Label", { Text = "Завершить смену Анны на @lily_rose?", Wrap = true })
    end,
}, function(ok) if ok then endShift() end end)
```

Надписи по умолчанию (по-английски) меняются для всего приложения: `ui.ConfirmText = { title = "Подтверждение", accept = "ОК", cancel = "Отмена" }`.

### Набор компонентов

Готовые элементы для типичного интерфейса с данными: значки, статусы, аватары, полосы выполнения, выбор из списка, выбор даты, таблицы и графики. Они раскрашены переменными темы (`ui.SetSkin`), поэтому подстраиваются под светлую и тёмную тему без перестройки страницы. Тексты по умолчанию английские; каждый меняется полем класса (`ui.GetClass("ListView").MoreText = "Загрузить ещё"`) или через `date.SetLocale` для календаря.

Там, где элементу нужен цвет (`SetColor`, цвет столбика или сегмента), можно передать `Color`, имя переменной приложения из `ui.SetVars` (`"series2"`), ключ темы (`"accent"`, `"success"`) или строку CSS.

#### Варианты кнопки

`Button:SetVariant(v)` меняет вид любой кнопки: `"primary"` (акцентная заливка, текст цвета `onAccent`), `"outline"` (прозрачная с рамкой), `"danger"` (красноватая, для опасных действий), `"ghost"` (без фона и рамки), `"default"` (обычная). `GetVariant()` возвращает текущий.

```lua
ui.Create("Button", row, { Text = "Сохранить", Variant = "primary" })
ui.Create("Button", row, { Text = "Удалить", Variant = "danger" })
```

#### Badge

Маленькая «таблетка» с текстом, наследник `Label`. `SetVariant(v)`: `"neutral"` (по умолчанию), `"accent"`, `"success"`, `"warning"`, `"danger"`.

```lua
ui.Create("Badge", row, { Text = "▲ +12.4%", Variant = "success" })
```

#### Status

#### Select

Кнопка, которая открывает список вариантов во всплывающем слое (`Popover`). В отличие от `ComboBox` список нарисован панелями и выглядит одинаково везде; в отличие от `Dropdown` у него есть подсказка-заглушка, выделение выбранного пункта и навигация стрелками.

| Метод | Описание |
| --- | --- |
| `SetPlaceholder(text)` | серый текст, пока ничего не выбрано |

| `SetOptions(list)` | заменить все пункты: строки, `{ text, data }` или `{ text = ..., data = ... }`. Выбор сохраняется, если пункт с теми же данными остался |
| `Clear()` | убрать пункты и выбор |
| `ChooseIndex(i)`, `SetValue(data)` | выбрать без события; `nil` снимает выбор |
| `GetValue()`, `GetSelected()`, `GetSelectedID()` | данные; текст и данные; номер |

Событие `OnSelect(self, index, text, data)` срабатывает, когда выбор изменил пользователь. Текст пустого списка задаёт поле `EmptyText`.

local models = ui.Create("Select", filters, { Placeholder = "Все модели", Wide = 180 })
models:SetOptions({ "@lily_rose", "@mia_vibes" })

Вращающееся кольцо цвета акцента, 22 на 22 пикселя (меняется `SetSize`). Анимацию делает браузер, Lua каждый кадр не вызывается.

#### ListView

Таблица, в которой все показанные строки лежат на странице: она растёт вместе с данными и прокручивается вместе со страницей, а не внутри себя. Для тысяч строк с виртуальной прокруткой используйте `DataGrid`, а здесь включите постраничный показ.

```lua
local list = ui.Create("ListView", self)
list:SetColumns({
    { key = "time", title = "Время", width = 120, sort = "ts" },
    { key = "sender", title = "Отправитель" },
    { key = "amount", title = "Сумма", width = 130, align = "right", sort = true,
      format = function(v) return "$" .. v end,
      style = { color = ui.Var("positive"), fontWeight = 500 } },
    { title = "Тип", width = 130, build = function(cell, row)
        cell:Add("Badge", { Text = row.type, Variant = "accent" })
    end },
})
list:SetRows(rows)
list:SetPageSize(50)
function list:OnRowClick(row) router.Go("/profits/" .. row.id) end
```

Поля колонки:

| Поле | Описание |
| --- | --- |
| `key` | поле строки, которое показывается в ячейке |
| `title` | заголовок |
| `width` | число (пиксели) или строка (`"1fr"`, `"auto"`); по умолчанию равные доли |
| `align` | `"right"` для чисел |
| `format(value, row, index)` | текст ячейки |
| `style` | таблица для `SetStyle` надписи или функция `(row, index)`, которая её возвращает |
| `build(cell, row, index)` | своя ячейка: функция наполняет панель `cell` чем угодно |
| `sort` | по колонке можно сортировать кликом по заголовку: `true` (по `key`), имя поля или функция `(row)`, возвращающая значение для сравнения. Строки сравниваются без учёта регистра, пустые значения в конце |
| `sortDesc` | `false`: первый клик сортирует по возрастанию (по умолчанию по убыванию) |

Методы:

| Метод | Описание |
| --- | --- |
| `SetColumns(columns)`, `SetRows(rows)` | колонки и строки (таблицы Lua) |
| `GetRows()`, `GetDisplayRows()` | строки как переданы; в порядке показа |
| `SetSort(index, desc)`, `GetSort()` | сортировка из кода; `nil` возвращает исходный порядок |
| `SetPageSize(n)`, `ShowMore()` | показывать первые `n` строк и кнопку «показать ещё» (текст в поле `MoreText`) |
| `SetMinWidth(px)` | уже этой ширины таблица прокручивается вбок внутри себя |
| `SetEmptyText(text)` | текст пустой таблицы (по умолчанию поле `EmptyText`) |
| `SetRowPadding(x, y)`, `SetRowHeight(px)` | отступы ячеек и минимальная высота строки |

События: `OnRowClick(self, row, index)` (строки получают вид «кликабельных»), `OnRowRightClick(self, row, index)` (контекстное меню браузера не показывается), `OnSort(self, column, desc)`, `OnRendered(self)`. Внутренние панели доступны как `Header`, `Body`, `Empty`, `Footer`, `MoreButton`; фон и рамку таблице задаёт приложение (`SetBackgroundColor`, `SetBorder`).

#### Dialog

Окно (наследник `Frame`) с современной раскладкой: шапка с заголовком и крестиком, прокручиваемое тело и подвал с кнопками. Высота подстраивается под содержимое, ширина по умолчанию 480. Новые дети попадают в тело (`Body` это слот по умолчанию).

```lua
local d = ui.Create("Dialog")
d:SetTitle("Удалить транзакцию")
d:Add("Label", { Text = "Действие необратимо.", Wrap = true })
d:AddButton("Удалить", "danger", function(dlg) remove(); dlg:Close() end)
d:AddButton("Отмена")
d:MakePopup()
```

`AddButton(text, [variant], [fn])` добавляет кнопку в подвал; без `fn` кнопка просто закрывает окно. Подвал появляется с первой кнопкой.

#### Графики

Четыре вида графиков. Цвета серий берутся из переменных приложения `series1` … `series6` (объявите их через `ui.SetVars` как `Color`, тогда графики перекрашиваются при смене темы); если переменных нет, используется встроенная палитра. У каждого графика есть текст для пустых данных (`SetEmptyText`, по умолчанию поле `EmptyText`).

`Sparkline`: маленькая линия без осей для карточек. `SetValues(list)`, `SetColor(c)`, `SetFill(b)` (заливка под линией, по умолчанию есть), `SetRingColor(c)` (кольцо вокруг точки на конце: цвет фона карточки, по умолчанию ключ темы `panel`). Высота по умолчанию 56.

`LineChart`: линия с подписями осей, сеткой и перекрестьем при наведении (подсказка показывает подпись точки и значение).

| Метод | Описание |
| --- | --- |
| `SetPoints(points, [color])` | одна серия: `{ { label = "01.11", value = 120 }, ... }` |
| `SetSeries(list)` | несколько: `{ { name = "...", color = ..., points = {...} }, ... }` |
| `SetFormat(fn)` | текст значений на оси и в подсказке: `fn(number) -> string` |

Шрифт и цвета подписей задаются полями класса: `Font` (по умолчанию `"Small"`), `LabelColor`, `GridColor`, `RingColor`, `TooltipColor`.

`BarChart`: столбики из панелей. `SetBars({ { label = ..., value = ..., color = ? }, ... })`, `SetOrientation("horizontal")` (строки с подписью, дорожкой и значением, по умолчанию) или `"vertical"` (столбцы, значение появляется при наведении), `SetFormat(fn)`, `SetColor(c)`, `SetMax(v)` (своя шкала вместо наибольшего значения), `SetPlotHeight(px)` для вертикального.

`DonutChart`: кольцо с итогом в центре и легендой с долями в процентах. `SetSlices({ { label = ..., value = ... }, ... })`, `SetCenterLabel(text)` (подпись под итогом), `SetFormat(fn)` (вид итога), `SetDiameter(px)` (по умолчанию 172), `SetThickness(px)`.

```lua
local donut = ui.Create("DonutChart", card, { CenterLabel = "всего" })
donut:SetFormat(function(v) return "$" .. math.floor(v) end)
donut:SetSlices({ { label = "PPV", value = 3990 }, { label = "Tip", value = 2140 } })
```

#### Calendar и DatePicker

`Calendar` показывает месяц сеткой и позволяет выбрать день. `DatePicker` это кнопка, которая открывает календарь во всплывающем слое. Дни представлены числом: секундами Unix местной полуночи (см. [Дата и время](#дата-и-время)), поэтому их удобно сравнивать и передавать на сервер.

| Метод | Описание |
| --- | --- |
| `Calendar:SetValue(day)`, `GetValue()` | выбранный день (любое время внутри дня) или `nil`; календарь переходит на его месяц |
| `Calendar:SetMonth(year, month)`, `GetMonth()` | показываемый месяц |
| `Calendar:SetRange(from, to)` | подсветить дни между двумя датами |
| `DatePicker:SetValue(day)`, `GetValue()` | выбранный день без события |
| `DatePicker:SetPlaceholder(text)` | текст, пока день не выбран |
| `DatePicker:SetFormat(pattern)` | вид даты на кнопке, шаблон `date.Format` (по умолчанию поле `Format`, `"D MMM YYYY"`) |

События: `Calendar.OnSelect(self, day)` и `DatePicker.OnChange(self, day)`, оба от действий пользователя. Сегодняшний день выделяется (по `date.Now()`). Названия месяцев и дней недели и первый день недели берутся из `date.SetLocale`.

### Собственные элементы на HTML-тегах

Если нужен элемент, которого нет в списке, задайте классу поле `Tag`, и панель получит этот тег:

```lua
local VIDEO = { Tag = "video" }

function VIDEO:Initialize()
    self:SetAttr("controls", true)
end

function VIDEO:SetSource(url) self:SetAttr("src", url) end
function VIDEO:Play() self:Invoke("play") end

ui.Register("Video", VIDEO, "Panel")
```

Для работы с такими элементами служат три метода. Все они ограничены белыми списками.

| Метод | Что делает |
| --- | --- |
| `SetAttr(name, value)`, `GetAttr(name)` | HTML-атрибут. Разрешены `aria-*`, `data-*` и перечень безобидных атрибутов: `role`, `title`, `alt`, `placeholder`, `name`, `id`, `tabindex`, `lang`, `dir`, `autocomplete`, `inputmode`, `min`, `max`, `step`, `pattern`, `required`, `controls`, `autoplay`, `loop`, `muted` и подобные. `true` создаёт пустой (логический) атрибут, `false` и `nil` удаляют. Адресные атрибуты `href`, `src`, `poster`, `cite` проверяются по тем же правилам, что `Link:SetURL`. Атрибуты `on*` (обработчики событий), `style`, `srcdoc` и другие опасные не разрешены. Для панелей-обёрток (`TextEntry`, `ComboBox`...) атрибут ставится на внутренний элемент (`<input>`) |
| `SetProp(name, value)`, `GetProp(name)` | свойство элемента (текущее состояние): `value`, `checked`, `selectedIndex`, `disabled`, `scrollTop`, `scrollLeft`, `muted`, `volume`, `currentTime`, `playbackRate` и другие. Читать можно ещё `duration`, `paused`, `ended`, `naturalWidth`, `naturalHeight`, `scrollHeight`, `clientWidth`... Значения только `nil`, булево, число или строка |
| `Invoke(method)` | вызвать метод элемента без аргументов: `"play"`, `"pause"`, `"load"`, `"select"`, `"showPicker"`, `"stepUp"`, `"stepDown"`, `"reportValidity"`, `"requestFullscreen"` |

Если нужен атрибут или свойство, которых нет в списках, это значит, что оно может быть небезопасным. В этом случае, скорее всего, нужен другой подход, а не обход проверки.

## Маршрутизация

Роутер связывает адрес в строке браузера со страницей (панелью класса на базе `Page`). Переход между страницами не перезагружает сайт, работают кнопки «назад» и «вперёд».

### Страница

```lua
local PAGE = {}
PAGE.Route = "/users/{id}"
PAGE.Title = "Пользователь"

function PAGE:Initialize()
    local user, err = http.Get("/api/users/" .. self.Params.id)
    if err then
        ui.Create("Label", self, { Text = err.message })
        return
    end
    ui.Create("Label", self, { Text = user.name })
end

ui.Register("UserPage", PAGE, "Page")
```

Поля класса страницы:

| Поле | Описание |
| --- | --- |
| `Route` | шаблон адреса, см. ниже |
| `Title` | заголовок вкладки. Можно менять в работе: `self:SetTitle("...")` |
| `Layout` | имя класса-лейаута или список имён от внешнего к внутреннему |
| `KeepAlive` | `true` сохраняет страницу при уходе с неё |
| `Guard` | функция проверки доступа |
| `Loader` | функция загрузки данных перед показом страницы |

Поля экземпляра, доступные уже в `Initialize`:

| Поле | Описание |
| --- | --- |
| `self.Path` | путь без query, например `"/users/5"` |
| `self.Params` | параметры из шаблона, например `{ id = "5" }`. Значения всегда строки; используйте `tonumber` |
| `self.Query` | параметры строки запроса: для `/users?tab=info` это `{ tab = "info" }`. Значения строки, при повторе ключа остаётся последнее |
| `self.Data` | то, что вернул `Loader` |

### Шаблоны адресов

- `{имя}` совпадает с одним сегментом пути: `/users/{id}` подходит к `/users/5`.
- `{*имя}` совпадает с остатком пути: `/files/{*path}` подходит к `/files/a/b/c.txt`, параметр `path` равен `"a/b/c.txt"`.
- Значения параметров раскодируются из процентной записи (`%20` становится пробелом).
- Если подходят несколько шаблонов, побеждает тот, где меньше параметров: `/users/new` выигрывает у `/users/{id}`. Шаблон с `{*...}` проигрывает всем.
- Слэш в конце адреса не важен.
- Синтаксис тот же, что у Rust-макросов `#[get("/api/users/{id}")]`.

Шаблон читается из поля `Route` в момент `ui.Register`. Поле наследуется только по классовой цепочке, а не по маршрутам: у класса, унаследованного от страницы с `Route`, свой маршрут должен быть задан заново (иначе страница остаётся только у базового класса).

Страницы из папки `lazy/` получают адрес из имени файла, см. [Структура приложения](#структура-приложения).

### Страница 404

Если адрес не подошёл ни к одному маршруту, показывается класс `NotFoundPage`, если вы его зарегистрировали, иначе встроенная страница «404». Через `self.Path` можно показать, чего не нашлось.

```lua
local PAGE = {}
function PAGE:Initialize()
    ui.Create("Label", self, { Text = "Страницы " .. self.Path .. " нет" })
end
ui.Register("NotFoundPage", PAGE, "Page")
```

### Переходы

| Функция | Что делает |
| --- | --- |
| `router.Go(url)` | перейти на адрес, добавив запись в историю |
| `router.Replace(url)` | перейти, заменив текущую запись (кнопка «назад» вернёт не сюда) |
| `router.Back()` | шаг назад по истории |
| `router.Reload()` | пересоздать текущую страницу (кеш `KeepAlive` очищается) |
| `router.Open(url)` | открыть в новой вкладке (то же, что `gui.OpenURL`); принимает `http`, `https`, `mailto` и относительные адреса, возвращает `true` или `false` |
| `router.GetPath()`, `router.GetPage()` | текущий путь и текущая страница |

Адрес может быть относительным (`"/users/5?tab=info"`). Элемент `Link` с адресом внутри сайта переходит через роутер сам.

### Лейауты

Лейаут это оболочка вокруг страницы: шапка, меню, подвал. Он создаётся один раз и остаётся, пока пользователь переходит между страницами с тем же лейаутом.

```lua
local LAYOUT = {}
function LAYOUT:Initialize()
    local header = ui.Create("Row", self, { Gap = 20 })
    header:Dock(DOCK_TOP)
    header:SetTall(54)
    ui.Create("Link", header, { Text = "Главная", URL = "/" })
    ui.Create("Link", header, { Text = "О нас", URL = "/about" })

    local outlet = self:Add("Panel")
    outlet:Dock(DOCK_FILL)
    self:SetOutlet(outlet)
end
ui.Register("AppLayout", LAYOUT, "Panel")

local PAGE = {}
PAGE.Route = "/about"
PAGE.Layout = "AppLayout"
ui.Register("AboutPage", PAGE, "Page")
```

- `SetOutlet(панель)` указывает, куда класть страницу. Без него страница кладётся в сам лейаут.
- `Layout = { "Outer", "Inner" }` вкладывает лейауты друг в друга. Общая начальная часть цепочки сохраняется при переходе, остальное пересоздаётся.
- У лейаута доступны `self.Path`, `self.Params`, `self.Query`, `self.Data` текущей страницы (они обновляются при каждом переходе).
- Лейаут растягивается на весь экран автоматически (`DOCK_FILL`).

### Guard: проверка доступа

```lua
PAGE.Guard = function(ctx)
    local me = http.Get("/api/me")
    if not me then return "/login" end
end
```

`Guard` вызывается перед показом страницы с таблицей `ctx` (`Path`, `Params`, `Query`) и может ждать ответа сервера. Это обычная функция, а не метод: пишите `PAGE.Guard = function(ctx)` или `function PAGE.Guard(ctx)` (с точкой), иначе `ctx` попадёт не туда.

| Результат | Что происходит |
| --- | --- |
| `nil` или `true` | страница показывается |
| `false` | доступ запрещён. Если на экране ещё нет страницы, показывается «Access denied»; иначе остаётся текущая. Переход «назад» или «вперёд» откатывается. Срабатывает хук `OnNavigationDenied(path)` |
| строка | перенаправление на этот адрес (до 12 переходов подряд) |

### Loader: данные до показа страницы

```lua
PAGE.Loader = function(ctx)
    local user, err = http.Get("/api/users/" .. ctx.Params.id)
    if err then return nil, err end
    return user
end

function PAGE:Initialize()
    ui.Create("Label", self, { Text = self.Data.name })
end
```

`Loader(ctx)` тоже обычная функция и тоже может ждать. Первый результат попадёт в `self.Data`. Если вернуть вторым значением ошибку (таблицу с полем `message` или строку), переход отменяется. Для страницы, восстановленной из кеша `KeepAlive`, `Loader` не вызывается.

### KeepAlive

`PAGE.KeepAlive = true` оставляет страницу живой (скрытой) при уходе с неё. При возвращении она появляется мгновенно, с прежней прокруткой, а `Initialize` не запускается заново. Запоминаются 8 последних адресов, самые старые удаляются. Модальные окна, открытые внутри такой страницы, закрываются при уходе. Страница, которая зависит от данных, должна сама их обновлять (`Panel:UseQuery`).

### Ошибки и хуки

| Хук | Когда |
| --- | --- |
| `OnPageChanged(path, page)` | страница показана |
| `OnNavigationDenied(path)` | `Guard` вернул `false` |
| `OnNavigationError(path, message)` | страницу не удалось подготовить: ошибка в `Guard` или `Loader`, не загрузился ленивый файл. Ошибки внутри `Initialize` сюда не попадают, они сообщаются как обычные ошибки обработчиков |

Если страница не загрузилась, а на экране ещё ничего нет, показывается панель с ошибкой и кнопкой «Retry». Если страница уже была на экране, она остаётся, а ошибка сообщается.

### Заголовок и метаданные

Заголовок вкладки берётся из `Page.Title` или `Page:GetTitle()` (его можно переопределить). Если у страницы нет заголовка, остаётся заголовок из `App::title`. Метатеги (`description`, `og:*`) меняются функцией `browser.SetMeta(name, content)`, см. [API браузера](#api-браузера). Для поисковых роботов, которые не выполняют WebAssembly, метатеги по умолчанию задаются на сервере методом `App::meta`.

### Как сервер отдаёт страницы

Для любого адреса, который не является файлом и не принадлежит API, сервер отвечает той же оболочкой, а роутер в браузере выбирает страницу. Подробности (что такое «адрес API», как это настраивается) в разделе [Rust: сервер](#rust-сервер).

## HTTP и данные

Модуль `http` отправляет запросы вашему серверу. Ответы в формате JSON превращаются в таблицы Lua.

### Простые запросы

```lua
local user, err = http.Get("/api/users/1")
local created, err = http.Post("/api/users", { name = "Ann" })
```

| Функция | Что делает |
| --- | --- |
| `http.Get(url, [opts])` | прочитать |
| `http.Post(url, [body], [opts])` | создать или отправить |
| `http.Put(url, [body], [opts])`, `http.Patch(...)` | заменить, изменить |
| `http.Delete(url, [body], [opts])` | удалить |
| `http.Request(method, url, [body], [opts])` | любой метод |

Все они возвращают два значения: `значение, ошибка`. При успехе ошибка равна `nil`, при неудаче значение равно `nil`. Эти функции ждут ответа (см. [Ожидание внутри обработчиков](#ожидание-внутри-обработчиков)): их можно вызывать только в обработчиках событий, таймерах и `Initialize`.

Что уходит на сервер:

- Таблица в `body` отправляется как JSON с заголовком `Content-Type: application/json`. Строка отправляется как текст. Без `body` тела нет.
- Преобразование таблицы Lua в JSON: таблица с ключами ровно от 1 до n становится массивом, остальные объектом. Пустая таблица `{}` становится массивом `[]`, а не объектом. Целые числа в виде дробей (`5.0`) отправляются как целые. Ключи со значением `nil` пропадают. Вложенность не более 64 уровней. Функции и потоки в JSON не превращаются (ошибка).

Что приходит:

- Если ответ помечен как JSON, он превращается в таблицу (`null` становится `nil`, числа без дробной части целыми). Остальные ответы приходят строкой. Ответ без тела (например, `204 No Content`) даёт пустую строку.
- Статусы `200`..`299` это успех. Остальное (и сетевые ошибки) возвращает `nil, err`.

Таблица `err`:

| Поле | Описание |
| --- | --- |
| `status` | HTTP-статус; `0` для сетевой ошибки, тайм-аута и отмены |
| `message` | текст ошибки: тело ответа, если это строка; поле `message` из JSON; иначе `"HTTP 500"` |
| `body` | тело ответа (таблица или строка) |
| `fields` | таблица `имя_поля -> список сообщений`, если сервер вернул `422` с `FieldErrors`, см. [Формы и валидация](#формы-и-валидация) |
| `timeout`, `cancelled` | `true`, если запрос оборван по тайм-ауту или отменён |

Если сервер вместо ответа вернул вашу страницу-оболочку (то есть такого адреса на сервере нет), вы получите `404` с сообщением `no such endpoint`, а не «успех с HTML».

### Параметры запроса

Третий или четвёртый аргумент `opts` это таблица:

| Ключ | Описание |
| --- | --- |
| `headers` | дополнительные заголовки `{ ["X-Token"] = "abc" }`; значение `false` убирает заголовок, заданный через `http.SetHeader` |
| `timeout` | тайм-аут в секундах, `0` без тайм-аута. По умолчанию 30 (меняется `http.SetTimeout`) |
| `invalidate` | строка или список префиксов, которые нужно сбросить в кеше после успешного ответа (см. ниже) |

В адрес запроса подставляйте только закодированные значения: `"/api/search?q=" .. http.Encode(text)`. `http.Encode` заменяет спецсимволы процентной записью.

### Заголовки и тайм-ауты по умолчанию

- `http.SetHeader(name, value)` добавляет заголовок ко всем запросам к вашему сайту (`nil` убирает). Например, `http.SetHeader("Authorization", "Bearer " .. token)`. Заголовки по умолчанию никогда не отправляются на другие origin: они часто несут пароли и токены.
- `http.SetTimeout(seconds)` меняет стандартный тайм-аут. `0` или `nil` отключает.
- Cookie браузер прикладывает к запросам на ваш сайт сам.
- Ответ `401` от вашего сайта вызывает хук `Unauthorized(url, err)`. Это удобное единое место, чтобы отправить пользователя на страницу входа:

```lua
hook.Add("Unauthorized", "login-redirect", function(url, err)
    if router.GetPath() ~= "/login" then router.Go("/login") end
end)
```

### Запросы без ожидания

| Функция | Описание |
| --- | --- |
| `http.Start(method, url, [body], [opts])` | отправить запрос и сразу получить объект `HttpRequest`. Не привязан к панели |
| `req:Wait()` | дождаться результата (только в обработчиках) |
| `req:Cancel()` | отменить; ожидающий получит `nil, { status = 0, cancelled = true }` |
| `req:IsDone()` | завершён ли запрос |
| `http.Fetch(url, onSuccess, onFailure, [method], [body], [opts])` | вариант с обратными вызовами, работает где угодно. `onSuccess(value)`, `onFailure(message, err)` |

Запросы, начатые в обработчике через `http.Get` и подобные, автоматически отменяются, если панель обработчика удалена. Запросы через `http.Start` и `http.Fetch` отменяйте сами.

Пример поиска, где каждое нажатие отменяет прошлый запрос:

```lua
local pending
function entry:OnValueChange(text)
    if pending then pending:Cancel() end
    pending = http.Start("GET", "/api/search?q=" .. http.Encode(text))
    local found, err = pending:Wait()
    if err then return end
    results:Clear()
    for _, u in ipairs(found) do
        ui.Create("Label", results, { Text = u.name })
    end
end
```

### Загрузка файлов

`http.Upload(url, input, [field], [opts])` отправляет выбранные в `FileInput` файлы методом `POST` как `multipart/form-data` (так отправляются файлы из HTML-форм). `field` это имя поля, по умолчанию `"file"`. Работает только в обработчиках. На сервере это `axum::extract::Multipart` (в `axum` нужна функция `multipart`).

```lua
local files = ui.Create("FileInput", self, { Multiple = true })
function files:OnChange(input, selected)
    if #selected == 0 then return end
    local names, err = http.Upload("/api/upload", self)
    ui.Toast(err and err.message or table.concat(names, ", "))
end
```

### Кеш запросов

Для данных, которые читают несколько страниц, есть кешируемый `GET`.

| Функция | Описание |
| --- | --- |
| `http.Query(url, [opts])` | как `http.Get`, но с кешем. `opts.ttl`: сколько секунд ответ считается свежим (не меньше 2); `opts.key`: ключ кеша (по умолчанию сам адрес); остальные ключи как у обычных запросов |
| `Panel:UseQuery(url, [opts])` | то же, и панель подписывается на изменения |
| `http.GetData(key)` | посмотреть кеш без запроса |
| `http.SetData(key, value)` | записать значение в кеш (оптимистичное обновление) и уведомить подписчиков |
| `http.Invalidate([prefix])` | пометить записи устаревшими. Префикс `/api/users` подходит к `/api/users`, `/api/users/1`, `/api/users?q=a`, но не к `/api/usersettings`. Без аргумента сбрасывается всё. Записи, на которые подписаны панели, сразу запрашиваются заново, остальные удаляются |

Правила работы:

- Параллельные вызовы с одним ключом делятся одним запросом, а ответы моложе 2 секунд берутся из кеша.
- Свежий ответ (моложе `ttl`) возвращается из кеша сразу.
- Устаревший ответ возвращается сразу же, а в фоне запрашивается новый. Если ответ изменился, подписанные панели получают уведомление.
- Возвращаемая таблица общая для всех: не изменяйте её, а копируйте через `table.Copy`.
- Если у подписанной панели есть метод `OnQueryUpdate(key, value)`, он вызывается при изменении данных. Без него панель перестраивается (`Rebuild`).

```lua
function PAGE:Initialize()
    local user, err = self:UseQuery("/api/users/" .. self.Params.id)
    if err then return end
    ui.Create("Label", self, { Text = user.name })
end
```

После изменения данных сбросьте кеш, и все открытые страницы обновятся:

```lua
http.Post("/api/users/1/rename", { name = "Ann" }, { invalidate = "/api/users" })
```

## Реактивное состояние

Состояние (state) это значение, за изменением которого следят панели и вычисления. Когда оно меняется, обновляются только те свойства, которые от него зависят.

```lua
local count = ui.State(0)

ui.Create("Label", self, { Text = ui.Computed(function() return "Нажато: " .. count() end) })
ui.Create("Button", self, {
    Text = "+1",
    DoClick = function() count:Update(function(n) return n + 1 end) end,
})
```

### Состояние

`ui.State(value)` создаёт ячейку.

| Метод | Описание |
| --- | --- |
| `state:Get()` или `state()` | прочитать значение и подписать на него текущее вычисление или эффект |
| `state:Peek()` | прочитать без подписки |
| `state:Set(v)` | записать. Если новое значение равно старому (`rawequal`), ничего не происходит |
| `state:Update(fn)` | записать `fn(старое)` |
| `state:Notify()` | сообщить об изменении таблицы, которую вы поменяли «на месте» (`Set` его не заметит) |
| `state:Subscribe(fn, [owner])` | вызывать `fn(значение)` после каждого изменения (не сразу). Возвращает функцию отписки. С `owner` подписка умирает вместе с панелью |

### Вычисляемое значение

`ui.Computed(fn)` это значение, которое выводится из других состояний. Оно пересчитывается лениво: только когда его прочитали после изменения исходных данных. Цепочки вычисляемых значений согласованы, эффект никогда не видит полуобновлённое состояние. Методы: `Get()` (или вызов как функции), `Peek()`, `Subscribe()`. Записывать нельзя.

### Эффект

`ui.Effect(fn, [owner])` запускает `fn` сразу и повторно каждый раз, когда изменилось состояние, прочитанное внутри. `fn` может вернуть функцию очистки, которая вызывается перед следующим запуском и при отключении. Возвращает функцию отключения (с `owner` эффект отключается сам вместе с панелью, у панели есть сокращение `panel:Effect(fn)`). Если эффекты по кругу меняют то, что читают, после 100 проходов цикл прерывается ошибкой.

### Вспомогательные функции

| Функция | Описание |
| --- | --- |
| `ui.Batch(fn)` | несколько `Set` внутри `fn`, а эффекты выполнятся один раз после |
| `ui.Untrack(fn, ...)` | выполнить `fn`, не подписываясь на прочитанные состояния |
| `ui.IsState(v)` | это состояние или вычисляемое значение? |

### Привязка к панелям

Есть два способа.

1. Через свойство при создании: любое свойство со значением-состоянием привязывается автоматически (`{ Text = state }`, `{ Enabled = computed }`).
2. Через метод `panel:Bind([свойство], источник, [формат])`.

`свойство` это имя без `Set`: для `"Text"` будет вызываться `SetText`. Если не указать, берётся `BindDefault` класса (`Text` у надписей, `Value` у полей ввода, `Checked` у флажка, `Fraction` у полосы прогресса, `Image` у картинки, `Title` у окна и страницы). `источник` может быть состоянием, вычисляемым значением или функцией (она станет вычисляемым значением). `формат(v)` преобразует значение перед записью. При каждом изменении вызывается только сеттер связанного свойства. Привязки снимаются вместе с панелью и при `Rebuild`.

Для полей ввода, флажков и списков с обычным `ui.State` без `формат` привязка двусторонняя: что пользователь ввёл, записывается обратно в состояние.

```lua
local name = ui.State("Олежек")
ui.Create("TextEntry", self, { Value = name })
ui.Create("Label", self, { Text = ui.Computed(function() return "Привет, " .. name() .. "!" end) })
```

`panel:Unbind([свойство])` снимает привязку.

## Рисование

Панель, у которой есть метод `Paint`, получает холст (элемент `<canvas>` на заднем плане) и сама рисует на нём линии, фигуры, текст и картинки. Это нужно для графиков, индикаторов и нестандартных элементов.

```lua
local CHART = {}

function CHART:Initialize()
    self:SetTall(240)
    self.Values = { 30, 80, 55 }
end

function CHART:Paint(w, h)
    draw.RoundedBox(10, 0, 0, w, h, Color(37, 40, 45))
    local bw = (w - 40) / #self.Values
    for i, v in ipairs(self.Values) do
        local bh = (h - 40) * v / 100
        draw.RoundedBoxEx(4, 20 + (i - 1) * bw + 3, h - 20 - bh, bw - 6, bh, Color(92, 156, 255), true, true, false, false)
    end
    draw.SimpleText("Продажи", "DefaultBold", 20, 10, color_white)
end

ui.Register("BarChart", CHART, "Panel")
```

Правила:

- `Paint(w, h)` получает размер панели в пикселях. Начало координат в левом верхнем углу панели.
- Paint вызывается не каждый кадр, а только при инвалидации: при создании, при изменении размера, при наведении курсора и нажатии, при смене фокуса и состояния, при изменении текста надписи, после загрузки шрифта и по явному вызову `panel:InvalidatePaint()`. Поменяли данные, от которых зависит рисунок, вызовите `InvalidatePaint()`.
- `panel:SetPaintEveryFrame(true)` перерисовывает панель каждый кадр (для анимации). Не включайте без нужды.
- Для плавной анимации по состоянию используйте `Think`, меняйте значение и вызывайте `InvalidatePaint()` только тогда, когда оно действительно изменилось:

```lua
function BTN:Think()
    local target = self:IsHovered() and 1 or 0
    if self.Fade == target then return end
    self.Fade = Lerp(math.min(FrameTime() * 10, 1), self.Fade, target)
    self:InvalidatePaint()
end
```

- Если у панели есть `Paint`, обычный фон, рамка и тень панели не показываются: вы рисуете сами. Дети и текст рисуются поверх холста.
- `Paint` можно назначить и конкретной панели: `button.Paint = function(self, w, h) ... end`.
- Внутри `Paint` нельзя ждать ответа сервера. Ошибка в `Paint` сообщается, но не ломает страницу.
- При каждом вызове `Paint` состояние рисования сбрасывается: шрифт `"Default"`, позиция текста 0, 0, материал не выбран, цвет белый, толщина линии 1, концы и стыки линий по умолчанию, сплошная линия.

### surface: низкоуровневое рисование

| Функция | Описание |
| --- | --- |
| `surface.SetDrawColor(r, g, b, [a])` или `(Color)` | цвет для следующих фигур |
| `surface.DrawRect(x, y, w, h)` | заполненный прямоугольник |
| `surface.DrawOutlinedRect(x, y, w, h, [thickness])` | рамка |
| `surface.DrawLine(x1, y1, x2, y2)` | линия текущей толщины |
| `surface.DrawCircle(x, y, radius, [r, g, b, a])` | окружность без заливки (с заливкой: `draw.Circle`) |
| `surface.DrawPoly(verts)` | заполненный многоугольник, `verts = { { x = 0, y = 0 }, { x = 10, y = 0 }, ... }` |
| `surface.DrawArc(x, y, radius, from, to, [fill])` | дуга окружности. Углы в градусах: 0 смотрит вправо, углы растут по часовой стрелке, поэтому верх это `-90`. С `fill = true` рисуется закрашенный сектор |
| `surface.DrawPath(d, [mode], [x, y], [sx], [sy])` | фигура по данным SVG-пути (`"M3 17l6-6 4 4 8-8"`: прямые, дуги, кривые Безье). `mode`: `"fill"` (по умолчанию), `"stroke"` или `"both"`. Фигура масштабируется на `sx`, `sy` (`sy` по умолчанию равен `sx`) и сдвигается на `x`, `y`; толщина линии при этом не масштабируется |
| `surface.SetLineWidth(w)` | толщина линии в пикселях для `DrawLine`, `DrawCircle`, `DrawArc` и `DrawPath` с обводкой |
| `surface.SetLineCap(cap)` | концы линий: `"butt"` (по умолчанию, обрезаны), `"round"` (скруглены), `"square"` |
| `surface.SetLineJoin(join)` | стыки линий: `"miter"` (по умолчанию, острые), `"round"`, `"bevel"` (срезанные) |
| `surface.SetLineDash(pattern)` | пунктир: `{ штрих, промежуток, ... }` в пикселях; `nil` или `{}` возвращает сплошную линию |
| `surface.SetDrawGradient(x1, y1, x2, y2, stops)` | линейный градиент от точки `x1, y1` к `x2, y2` для следующих заливок и обводок, пока не вызван `SetDrawColor`. `stops`: список `Color` (расставляются равномерно) или `{ { 0, Color }, { 0.7, Color }, ... }` с долями от 0 до 1 |
| `surface.SetFont(name)`, `surface.GetFont()` | шрифт для текста |
| `surface.SetTextColor(r, g, b, [a])` или `(Color)` | цвет текста |
| `surface.SetTextPos(x, y)`, `surface.GetTextPos()` | позиция следующего текста |
| `surface.DrawText(text)` | вывести текст в текущей позиции; позиция сдвигается на ширину текста |
| `surface.GetTextSize(text)` | `w, h` текста в текущем шрифте. Работает и вне `Paint` (например, в `PerformLayout`) |
| `surface.SetAlphaMultiplier(a)` | общая прозрачность дальнейшего рисования, 0..1 |
| `surface.SetMaterial(mat)`, `surface.DrawTexturedRect(x, y, w, h)`, `surface.DrawTexturedRectUV(x, y, w, h, u0, v0, u1, v1)` | рисование картинки (целиком или фрагмента, `u` и `v` доли от 0 до 1) |

### Линии, контуры и градиенты

Этих функций достаточно для иконок и графиков. Иконки из наборов вроде Lucide или Feather это SVG-пути на сетке 24 на 24 с обводкой: возьмите атрибут `d` каждого `<path>` и нарисуйте его через `DrawPath` с нужным масштабом. Цвет иконки задаёт `SetDrawColor`, поэтому её легко перекрасить при наведении или смене темы. Окружности из SVG (`<circle cx="9" cy="7" r="4"/>`) записываются путём из двух дуг: `"M13 7a4 4 0 1 1-8 0a4 4 0 1 1 8 0"`.

```lua
local CHART_LINE = "M3 17l6-6 4 4 8-8"
local CHART_ARROW = "M14 7h7v7"

function ICON:Paint(w, h)
    local s = w / 24
    surface.SetDrawColor(self:IsHovered() and ui.GetVar("accent") or ui.GetVar("muted"))
    surface.SetLineWidth(1.8 * s)
    surface.SetLineCap("round")
    surface.SetLineJoin("round")
    surface.DrawPath(CHART_LINE, "stroke", 0, 0, s)
    surface.DrawPath(CHART_ARROW, "stroke", 0, 0, s)
end
```

Линейный график с заливкой, которая к низу становится прозрачной, и кольцевая диаграмма:

```lua
function CHART:Paint(w, h)
    local pts = {}
    for i, v in ipairs(self.Values) do
        pts[i] = string.format("%s%.1f %.1f", i == 1 and "M" or "L", w * (i - 1) / (#self.Values - 1), h * (1 - v / 100))
    end
    local line = table.concat(pts, " ")
    local c = ui.GetVar("accent")

    surface.SetDrawGradient(0, 0, 0, h, { Color(c.r, c.g, c.b, 40), Color(c.r, c.g, c.b, 0) })
    surface.DrawPath(line .. string.format(" L%d %d L0 %d Z", w, h, h), "fill")

    surface.SetDrawColor(c)
    surface.SetLineWidth(2)
    surface.SetLineJoin("round")
    surface.DrawPath(line, "stroke")
end

function DONUT:Paint(w, h)
    local angle = -90
    surface.SetLineWidth(16)
    for i, part in ipairs(self.Parts) do
        local sweep = 360 * part.share
        surface.SetDrawColor(part.color)
        surface.DrawArc(w / 2, h / 2, w / 2 - 8, angle, angle + sweep - 2)
        angle = angle + sweep
    end
end
```

Путь с ошибкой в данных браузер рисует до первой ошибки, остальное молча пропускает.

### Картинки

`Material(url)` загружает картинку по адресу и возвращает материал (повторные вызовы с тем же адресом возвращают тот же объект). Панели, которые нарисовали ещё не загруженную картинку, перерисовываются, когда она придёт.

## API браузера

### Хранилище

Модуль `storage` сохраняет данные в браузере (`localStorage`): они остаются после закрытия вкладки и общие для всех вкладок сайта. `storage.Session` хранит так же, но только до закрытия вкладки (`sessionStorage`).

| Функция | Описание |
| --- | --- |
| `storage.Get(key, [default])` | прочитать значение; если ключа нет, вернуть `default` |
| `storage.Set(key, value)` | записать (любое значение, которое превращается в JSON: число, строка, булево, таблица). `nil` удаляет ключ. Возвращает `false`, если браузер отказался (приватный режим, переполнение): тогда значение хранится в памяти до закрытия страницы |
| `storage.Remove(key)`, `storage.Clear()` | удалить ключ; удалить все ключи этого приложения (чужие данные сайта не трогаются) |
| `storage.Keys()` | список ключей |

Ключи хранятся с префиксом `ngs:`. Если другая вкладка изменила хранилище, срабатывает хук `OnStorageChanged(key, value)`. Любой скрипт на странице может прочитать `localStorage`, поэтому секретные токены в нём хранить не стоит: безопаснее cookie с флагом `HttpOnly`, которую ставит сервер.

### Cookie

Cookie это маленькие данные, которые браузер сам отправляет серверу с каждым запросом.

| Функция | Описание |
| --- | --- |
| `cookie.Get(name, [default])` | прочитать. Не видит cookie с флагом `HttpOnly` (например, сессионную) |
| `cookie.Set(name, value, [maxAge])` | записать. `maxAge` в секундах, без него cookie живёт до закрытия браузера. Cookie ставится на весь сайт, с `SameSite=Lax`, а на HTTPS ещё и с `Secure` |
| `cookie.Remove(name)` | удалить |

### Буфер обмена

`clipboard.WriteText(text)` возвращает `true` или `false, ошибка`. `clipboard.ReadText()` возвращает `text` или `nil, ошибка`. Вызывать можно только в обработчиках (клик пользователя), а браузер может запросить разрешение или отказать. Работает на HTTPS и на `localhost`.

### Тема системы и метатеги

- `browser.ColorScheme()` возвращает `"dark"` или `"light"` по настройке системы. Хук `OnColorSchemeChanged(scheme)` срабатывает при переключении.
- `browser.Now()` возвращает текущее время по часам браузера в секундах Unix (дробная часть это миллисекунды). `browser.TimezoneOffset([unix])` возвращает смещение часового пояса браузера от UTC в секундах для указанного момента (по умолчанию для текущего): с учётом перехода на летнее время. Считать даты удобнее модулем [`date`](#дата-и-время), который сам пользуется этими функциями.
- `browser.HasFocus()` сообщает, что окно страницы сейчас в фокусе (пользователь работает именно в нём). `browser.IsVisible()` возвращает `false`, пока вкладка в фоне или окно свёрнуто. При изменениях срабатывают хуки `OnWindowFocusChanged(focused)` и `OnVisibilityChanged(visible)`. Пример: обновить данные, когда пользователь вернулся на вкладку:

```lua
function PAGE:Initialize()
    self:Hook("OnVisibilityChanged", function(visible)
        if visible then http.Invalidate("/api/me") end
    end)
end
```
- `browser.SetMeta(name, content)` ставит метатег (`description`, `og:title`...). `nil` убирает тег. Для имён с `og:` используется атрибут `property`.

### Дата и время

В Lua нет `os.time` и `os.date`, поэтому для дат есть модуль `date`. Время хранится числом: секунды Unix (с 1 января 1970 года по UTC). Текущее время берётся с часов браузера (`browser.Now`), а «местное» время считается в часовом поясе браузера, с учётом перехода на летнее время для каждой даты отдельно.

Если часам пользователя доверять нельзя или все даты нужно показывать в поясе сервера (например, у агентства одно рабочее время), приложение один раз задаёт свои значения: `date.SetNow(время_сервера)` и `date.SetOffset(смещение)`. После этого `date.Now()` идёт от времени сервера, а все местные даты считаются в заданном смещении.

```lua
local today = date.StartOfDay(date.Now())
local month = date.StartOfMonth(date.Now())
local ts = date.Parse("2026-11-26T18:41:00Z")
print(date.Format(ts, "DD.MM HH:mm"))   -- "26.11 21:41" в поясе UTC+3
```

| Функция | Описание |
| --- | --- |
| `date.Now()` | текущее время в секундах Unix |
| `date.SetNow(unix)` | взять другие часы (например, сервера): дальше `Now()` идёт от этого значения по `CurTime()` |
| `date.SetOffset(seconds)` | постоянное смещение местного времени от UTC в секундах (Москва `10800`); `nil` возвращает пояс браузера |
| `date.GetOffset([unix])` | смещение, которое действует в этот момент (по умолчанию сейчас) |
| `date.Parse(s)` | строку ISO 8601 (`"2026-11-26"`, `"2026-11-26T18:41:00.5Z"`, `"...+03:00"`) в секунды; без пояса считается UTC; ошибка даёт `nil` |
| `date.ISO(unix)` | обратно: `"2026-11-26T18:41:00Z"` (для запросов к серверу) |
| `date.Time(y, m, d, [hh, mm, ss], [offset])` | секунды для местного времени. Месяц и день могут «переполняться»: `date.Time(2026, 13, 1)` это 1 января 2027 |
| `date.Fields(unix, [offset])` | таблица `year, month, day, hour, min, sec, wday` (1 понедельник … 7 воскресенье), `yday` |
| `date.Format(unix, pattern, [offset])` | текст по шаблону (см. ниже) |
| `date.StartOfDay`, `date.StartOfMonth` | начало дня и месяца |
| `date.AddDays(unix, n)`, `date.AddMonths(unix, n)` | календарные сдвиги (31 января + 1 месяц = 28 или 29 февраля) |
| `date.SameDay(a, b)`, `date.DaysInMonth(y, m)`, `date.IsLeap(y)` | помощники |
| `date.SetLocale(t)`, `date.GetLocale(key)` | названия: `months` (12 полных), `monthsShort`, `weekdaysShort` (7, с понедельника), `firstWeekday` (1 понедельник, 7 воскресенье) |

Шаблон `date.Format`: `YYYY` год, `YY` две цифры года, `MMMM` месяц словом, `MMM` коротко, `MM` и `M` номер месяца с нулём и без, `DD` и `D` день, `HH` и `H` часы, `mm` минуты, `ss` секунды, `dd` день недели коротко. Текст в квадратных скобках выводится как есть: `"D MMMM [в] HH:mm"`.

Последний аргумент `offset` у функций позволяет считать в другом поясе, например `0` для UTC.

### WebSocket и Server-Sent Events

WebSocket это постоянное двустороннее соединение с сервером, подходит для чатов и живых данных. Server-Sent Events (SSE) это поток сообщений от сервера к странице (односторонний).

```lua
local socket = browser.WebSocket("/api/echo", {
    open = function(s) s:Send("привет") end,
    message = function(s, text) ui.Toast(text) end,
    error = function(s) ui.Toast("ошибка") end,
    close = function(s) end,
}, self)
```

| Функция | Описание |
| --- | --- |
| `browser.WebSocket(url, handlers, [owner])` | подключиться. Можно дать относительный адрес (`/api/echo`): современные браузеры сами подставят `ws://` или `wss://`. Для старых браузеров указывайте адрес целиком |
| `browser.EventSource(url, handlers, [owner])` | подключиться по SSE |
| `stream:Send(text)` | отправить текстовое сообщение (только WebSocket) |
| `stream:Close()` | закрыть |

`handlers` это таблица с необязательными функциями `open`, `message`, `error`, `close`; каждая получает поток и (для `message`) текст. `owner` это панель: когда её удалят, соединение закроется. Обработчики могут ждать ответов сервера. На сервере это обычные обработчики axum (`WebSocketUpgrade`, `Sse`). Политика безопасности по умолчанию разрешает соединения только со своим сайтом.

| Событие | Аргументы | Когда |
| --- | --- | --- |

## Формы и валидация

Данные, которые вводит пользователь, нужно проверять дважды: в браузере (чтобы сразу показать ошибку) и на сервере (потому что браузеру нельзя доверять). Фреймворк связывает обе проверки: сервер отвечает ошибками по полям, а форма в браузере показывает каждую рядом с нужным полем.

### Серверная часть (Rust)

```rust
use ngs_olezhek::{FieldErrors, Valid, Validate, post};
use axum::Json;
use serde::{Deserialize, Serialize};

#[derive(Deserialize)]
struct Signup {
    name: String,
    email: String,
    age: Option<u32>,
}

impl Validate for Signup {
    fn validate(&self, errors: &mut FieldErrors) {
        errors.check(!self.name.trim().is_empty(), "name", "имя не может быть пустым");
        errors.check(self.email.contains('@'), "email", "нужен адрес почты");
        errors.check(self.age.is_none_or(|a| a >= 14), "age", "регистрация с 14 лет");
    }
}

#[derive(Serialize)]
struct Created {
    id: u64,
}

#[post("/api/signup")]
async fn signup(Valid(body): Valid<Signup>) -> Json<Created> {
    Json(Created { id: 1 })
}
```

`Valid<T>` читает тело запроса как JSON (как `Json<T>`), десериализует его в `T` и вызывает `T::validate`. Если что-то не так, сервер отвечает статусом `422 Unprocessable Entity` и таким JSON:

```json
{
  "message": "необязательный текст для формы целиком",
  "errors": {
    "name": ["имя не может быть пустым"],
    "email": ["нужен адрес почты"]
  }
}
```

Ошибки возникают в двух случаях, и формат один и тот же:

- Тело не подошло под тип `T`: нет поля, неправильный тип, битый JSON. Для отсутствующего поля сообщение `"required"`, для неправильного типа текст ошибки `serde` без позиции в тексте. Вложенные поля называются через точку (`address.city`, `tags.0`). Ошибка без привязки к полю (битый JSON) идёт в `message`.
- `validate` добавил ошибки.

`Valid<T>` читает тело целиком, поэтому его нужно ставить последним аргументом обработчика, как любой экстрактор тела в axum.

#### FieldErrors

| Метод | Описание |
| --- | --- |
| `FieldErrors::new()` | пустой набор |
| `.field(name, message)` | добавить ошибку, вернуть набор (для цепочек) |
| `.add(name, message)` | добавить ошибку по ссылке (`&mut`). У одного поля может быть несколько сообщений |
| `.check(ok, name, message)` | добавить ошибку, если `ok` равно `false` |
| `.message(text)` / `.set_message(text)` | сообщение для формы в целом |
| `.get(name)` | сообщения поля (`&[String]`) |
| `.is_empty()` | нет ни ошибок, ни сообщения |
| `.result()` | `Err(self)`, если что-то добавлено, иначе `Ok(())`. Удобно в конце обработчика: `errors.result()?` |

`FieldErrors` реализует `IntoResponse`, поэтому обработчик может сам вернуть его, когда проверка требует чего-то, чего нет в `validate` (например, запроса в базу):

```rust
#[post("/api/promo")]
async fn promo(Valid(body): Valid<Promo>) -> Result<Json<PromoResult>, FieldErrors> {
    if !is_valid_code(&body.code) {
        return Err(FieldErrors::new().field("code", "такого кода нет"));
    }
    Ok(Json(PromoResult { discount: 15 }))
}
```

Ошибка без поля, например `FieldErrors::new().message("Промокод истёк")`, покажется над полями формы.

### Клиентская часть: виджет Form

```lua
local form = ui.Create("Form", self)
form:SetAction("POST", "/api/signup")
form:AddField("name", "TextEntry", { Label = "Имя", Required = true, PlaceholderText = "Гордон" })
form:AddField("email", "TextEntry", {
    Label = "Почта", Required = true, InputType = "email",
    Validate = function(v)
        if not v:match("^[^@%s]+@[^@%s]+%.[^@%s]+$") then return "Это не похоже на адрес почты" end
    end,
})
form:AddField("age", "TextEntry", { Label = "Возраст", Numeric = true, Hint = "Необязательно" })
local role = form:AddField("role", "ComboBox", { Label = "Роль" })
role:AddChoice("Игрок", "player", true)
role:AddChoice("Учёный", "scientist")
form:AddField("agree", "CheckBox", { Text = "Принимаю правила" })

function form:OnSuccess(account)
    ui.Toast("Аккаунт #" .. account.id .. " создан")

```

Что делает форма при нажатии на кнопку отправки или на Enter в однострочном поле:

1. Собирает значения полей в таблицу `{ имя_поля = значение }`.
2. Проверяет их на клиенте: обязательные поля, функции `Validate` полей, затем метод формы `Validate`. Если есть ошибки, показывает их и не отправляет запрос.
3. Вызывает `OnBeforeSubmit(values)`, если он есть.
4. Отправляет значения JSON-ом методом и по адресу из `SetAction`. Пока запрос идёт, кнопка отправки отключена; повторная отправка игнорируется.
5. Если пришёл `422` с полями, показывает каждую ошибку у своего поля. Если пришла другая ошибка, показывает её текст над полями (или вызывает `OnFailure`).
6. При успехе очищает ошибки и вызывает `OnSuccess(value)`.

#### Методы формы

| Метод | Описание |
| --- | --- |
| `form:SetAction(method, url, [opts])` | куда отправлять. `opts` как у `http.Request` (`headers`, `timeout`, `invalidate`) |
| `form:AddField(name, [class], [opts])` | добавить поле с подписью и местом для ошибки. `name` это ключ в теле запроса и имя поля в ошибках сервера. `class` по умолчанию `"TextEntry"`. Возвращает созданную панель ввода |
| `form:AddSubmit([text])` | кнопка отправки (по умолчанию «Submit») |
| `form:GetField(name)` | панель ввода по имени |
| `form:GetValues()`, `form:SetValues(values)` | прочитать и задать значения всех полей |
| `form:Check([values])` | выполнить клиентскую проверку, показать ошибки, вернуть `true` или `false` |
| `form:Submit()` | то же, что нажатие кнопки. Возвращает `value, err` как `http.Post`. Ждёт ответ, поэтому вызывайте из обработчика |
| `form:SetErrors(fields, [message])` | показать ошибки: `fields = { имя = "текст" или { "текст", ... } }`. Ошибки для имён без поля добавляются в общее сообщение |
| `form:ClearErrors()` | убрать все ошибки |

Параметры `AddField`:

| Ключ | Описание |
| --- | --- |
| `Label` | подпись над полем |
| `Hint` | серый пояснительный текст под полем |
| `Required` | пустое значение (`nil`, `false` или строка из пробелов) не пропускается |
| `RequiredMessage` | свой текст для этого поля вместо стандартного |
| `Value` | начальное значение |
| `Validate(value, values)` | функция проверки: верните текст ошибки, чтобы отклонить значение, или `nil`. Второй аргумент позволяет сравнить с другими полями |
| другие ключи | свойства для `ui.Create`: `PlaceholderText`, `InputType`, `Numeric`, `Text`, `MaxLength` и т. д. |

Обработчики формы (присваиваются как поля):

| Обработчик | Описание |
| --- | --- |
| `OnSuccess(self, value)` | запрос удался |
| `OnFailure(self, err)` | запрос не удался. Без него текст ошибки показывается над полями |
| `OnBeforeSubmit(self, values)` | вернуть таблицу, чтобы заменить тело запроса, или `false`, чтобы отменить отправку. Пригодится, чтобы убрать лишние поля или собрать вложенную структуру |
| `Validate(self, values)` | проверка, которой нужны несколько полей сразу. Верните таблицу `{ поле = "текст" }` или строку (ошибка формы в целом) |

Поведение, о котором стоит знать:

- Значение поля зависит от класса: `CheckBox` даёт `true` или `false`, `ComboBox` даёт данные выбранного пункта (`data` из `AddChoice`, а если их нет, текст), `TextEntry` с `InputType = "number"` или `Numeric = true` даёт число, остальные поля дают строку.
- Собственный класс можно подключить к форме, если определить в нём методы `GetFormValue()` и `SetFormValue(v)`.
- Имена с точкой (`address.city`) остаются плоскими ключами: тело запроса будет `{ ["address.city"] = ... }`. Если сервер ждёт вложенный объект, соберите его в `OnBeforeSubmit`. Ошибки сервера для `address.city` попадут в поле с таким же именем.
- Редактирование поля убирает его ошибку: она относилась к старому значению.
- Поле с ошибкой получает красную рамку и атрибут `aria-invalid` (для скринридеров), текст ошибки показывается под ним.
- Стандартный текст «Required» задаётся одной строкой для всего приложения: `ui.GetClass("Form").RequiredMessage = "Обязательное поле"` (в файле из `autorun/`).
- Форма доступна как панель: `form.Message` это надпись для ошибки всей формы, `form.SubmitButton` кнопка отправки.

### Ручная обработка

Форма не обязательна. Ответ `422` разбирается и вручную: поля `err.fields` совпадают с именами панелей, заданными через `SetName`.

```lua
local code = ui.Create("TextEntry", row)
code:SetName("code")

apply.DoClick = function()
    local promo, err = http.Post("/api/promo", { code = code:GetValue() })
    if err then
        local rest = ui.ApplyErrors(section, err.fields)
        status:SetText(next(rest) and err.message or "")
        return
    end
    ui.ApplyErrors(section, {})
end
```

| Функция | Описание |
| --- | --- |
| `ui.ApplyErrors(root, fields)` | ставит ошибки на панели внутри `root`, у которых `SetName` совпадает с ключом в `fields`; у остальных именованных панелей ошибка снимается. Возвращает ошибки, которым не нашлось панели, как таблицу `{ имя = "текст" }` |
| `panel:SetError(message)` | пометить одну панель ошибкой (`nil` или `false` убирает) |
| `panel:GetError()` | текущий текст ошибки |
| `OnErrorChanged(self, message)` | метод панели, вызывается при смене ошибки |

## Rust: сервер

### Подключение и основа

```rust
use ngs_olezhek::{App, include_lua};

#[tokio::main]
async fn main() {
    let app = App::new()
        .title("Мой сайт")
        .lua(include_lua!("lua"))
        .public("public");
    app.serve("0.0.0.0:3000").await.unwrap();
}
```

Библиотека реэкспортирует `axum` (`ngs_olezhek::axum`), макросы маршрутов, `FieldErrors`, `Valid`, `Validate`, `LuaType`, `ClientError`, `LuaSource`, `EmbeddedLua`, `Error`, `DEFAULT_CSP`, `lua_types` и модуль `security`. Модуль `testing` включается функцией `testing`.

### App: настройка

`App` собирается цепочкой вызовов. Все методы необязательны.

| Метод | По умолчанию | Описание |
| --- | --- | --- |
| `App::new()` | | создать приложение |
| `.lua(source)` | папка `"lua"` | откуда брать Lua: путь к папке (читается во время работы) или `include_lua!("lua")` (код вшивается в бинарник) |
| `.public(dir)` | нет | папка со статическими файлами (картинки, шрифты, иконки): отдаются как есть. Всё, чего там нет, обрабатывает приложение |
| `.api(router)` | пусто | подключить маршруты API. Можно вызывать много раз, маршруты объединяются |
| `.title(text)` | `"App"` | заголовок вкладки до запуска Lua |
| `.meta(name, content)` | | метатег в оболочке страницы (`description`, `og:image`...), виден до запуска WebAssembly: поисковым системам и превью ссылок. Имена с `og:` выводятся как `property`. Значения экранируются |
| `.dev(bool)` | `cfg!(debug_assertions)` | режим разработки, см. [Быстрый старт](#режимы-dev-и-release) |
| `.strip(bool)` | `!dev` | убрать из байткода номера строк и имена локальных переменных |
| `.api_prefix(prefix)` | `"/api"` | неизвестные адреса с этим префиксом отвечают 404, а не страницей приложения. Пустая строка отключает проверку |
| `.content_security_policy(HeaderValue)` | `DEFAULT_CSP` | политика безопасности контента, см. [Безопасность](#безопасность) |
| `.csrf(bool)` | `true` | защита от подделки межсайтовых запросов. Отключать только если эту работу делает что-то перед приложением |
| `.trust_origin(origin)` | | принимать запросы, изменяющие данные, со страниц другого origin (`"https://admin.example.com"`) |
| `.sessions(Sessions)` | выключено | сессии на cookie для маршрутов API |
| `.cors(Cors)` | выключено | CORS; указанные origin автоматически становятся доверенными для CSRF |
| `.on_client_error(fn)` | вывод в stderr | обработчик Lua-ошибок из браузеров (release) |
| `.client_errors(bool)` | `true` | `false` не даёт браузерам отправлять ошибки и убирает адрес `/_ngs/errors` |
| `.client_error_limit(RateLimit)` | 30 в минуту на адрес клиента, всплеск 10 | ограничение частоты для `/_ngs/errors` |
| `.into_router()` | | собрать `axum::Router` (возвращает `Result<Router, Error>`) |
| `.serve(addr)` | | собрать и запустить на адресе вроде `"127.0.0.1:3000"`. Печатает адрес и режим в консоль |

Если `serve` вызывается в режиме dev, при старте записываются файлы для редактора (`.ngs/`). Сервер при запуске не стартует, если не удалось прочитать папку Lua или (в release) в Lua есть ошибки компиляции: сообщение возвращается как `Error::Lua(Vec<String>)` (по одному на сломанный файл) или `Error::Io`.

`into_router` нужен для тестов и для запуска вручную. Если вы запускаете сервер сами, используйте `router.into_make_service_with_connect_info::<std::net::SocketAddr>()`: иначе ограничитель частоты (`RateLimit`) не узнает адрес клиента, и все посетители попадут в одну корзину. `serve` делает это сам.

### Маршруты API

Маршруты API это обычные обработчики axum. Макросы позволяют записать путь и метод прямо над функцией.

```rust
use axum::{Json, http::StatusCode};
use ngs_olezhek::{get, post, routes};
use serde::{Deserialize, Serialize};

#[derive(Serialize)]
struct User { id: u64, name: String }

#[get("/api/users/{id}")]
async fn get_user(id: u64) -> Result<Json<User>, StatusCode> {
    Err(StatusCode::NOT_FOUND)
}

#[get("/api/search")]
async fn search(#[query] q: String, #[query] limit: Option<u32>) -> Json<Vec<User>> {
    Json(vec![])
}

#[derive(Deserialize)]
struct NewUser { name: String }

#[post("/api/users")]
async fn create_user(Json(body): Json<NewUser>) -> Json<User> {
    Json(User { id: 1, name: body.name })
}

let api = routes![get_user, search, create_user];
```

Макросы: `#[get]`, `#[post]`, `#[put]`, `#[delete]`, `#[patch]`, `#[head]`, `#[options]`, `#[trace]`. Для нескольких методов на одном обработчике: `#[route("/path", GET, POST)]`.

Правила:

- В пути пишутся полные адреса, включая `/api`. Параметры задаются как `{имя}`, остаток пути как `{*имя}`, фигурные скобки как литералы пишутся удвоенными `{{`, `}}`.
- Аргумент функции с тем же именем, что параметр пути, получает значение из пути. Тип должен уметь десериализоваться из строки (`u64`, `String`, `uuid::Uuid`...). Если ни один аргумент не совпал с параметром, `Path` не добавляется, и вы можете написать его вручную.
- Аргумент с атрибутом `#[query]` берётся из строки запроса. Для необязательных параметров используйте `Option<T>`. Для этого в вашем крейте нужен `serde` с `derive`.
- Остальные аргументы это обычные экстракторы axum (`Json<T>`, `Valid<T>`, `Session`, `State<S>`...). Экстрактор тела должен стоять последним.
- `routes![a, b, users::c]` собирает `axum::Router`. Путь к функции указывается так же, как она импортирована.
- Имя функции с атрибутом создаёт рядом скрытый модуль с тем же именем (в нём лежат путь и метод), поэтому в одной области видимости нельзя держать функцию и другой модуль с таким же именем.
- Имена `get` и `post` из `ngs_olezhek` совпадают с функциями `axum::routing::get` и `post`. Если нужны обе, вызывайте маршрутизацию axum полностью: `axum::routing::get(handler)`.

Состояние приложения подключается как в axum: `routes![a, b].with_state(state)`. Ограничения применяются к группе маршрутов через `.layer`:

```rust
App::new()
    .api(routes![get_user, search])
    .api(routes![login].layer(RateLimit::per_minute(5)))
```

WebSocket, SSE и приём файлов делаются обычными средствами axum: `axum::routing::get(echo)` с `WebSocketUpgrade`, `Sse`, `Multipart` (в `axum` нужны функции `ws` и `multipart`). Добавьте такой роутер через `.api(Router::new().route(...))`.

### Служебные адреса `/_ngs`

Префикс `/_ngs` зарезервирован фреймворком.

| Адрес | Что отдаёт |
| --- | --- |
| `/_ngs/runtime.js`, `/_ngs/runtime_bg.wasm` | клиентский рантайм (с `ETag`, `Cache-Control: no-cache`, сжатием) |
| `/_ngs/style.css` | базовые стили элементов |
| `/_ngs/bundle` | стартовый пакет Lua-байткода |
| `/_ngs/page/{имя}` | ленивые модули из `lazy/` |
| `/_ngs/live` | WebSocket для горячей перезагрузки (только dev) |
| `/_ngs/errors` | приём Lua-ошибок из браузеров (release, если включено) |

### Какие адреса отдают страницу приложения

Любой адрес, который не нашёл ни API, ни статического файла, получает страницу-оболочку, а дальше роутер в браузере выбирает страницу. Но только если запрос похож на открытие страницы:

- метод `GET` или `HEAD`;
- адрес не начинается с `/_ngs` и не лежит под `api_prefix`;
- если браузер прислал заголовок `Sec-Fetch-Mode`, он должен быть `navigate`; иначе заголовок `Accept` отсутствует или содержит `text/html` или `*/*`.

Остальное (опечатка в адресе API, запрос `fetch` к несуществующему адресу, отсутствующий шрифт) получает `404 Not Found`, а не `200` с HTML. Страница-оболочка помечается заголовком `x-ngs-shell: 1`; на его основе клиент отличает «такого адреса нет» от настоящего ответа.

### Заголовки безопасности

К каждому ответу добавляются (если вы не задали их сами): `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, а в release ещё и `Strict-Transport-Security: max-age=31536000`.

### Lua-код: папка или встраивание

- `.lua("lua")` читает папку с диска. В release пакет собирается один раз при старте. Папка должна лежать рядом с программой на сервере.
- `.lua(include_lua!("lua"))` компилирует папку в байткод при сборке Rust-проекта и вшивает в бинарник. Путь считается от `Cargo.toml` вашего крейта. Синтаксическая ошибка в Lua ломает сборку. В режиме dev, если папка есть на диске, используются живые файлы (горячая перезагрузка работает и со встраиванием).

Новый файл в папке `lua` не заставляет Cargo пересобрать проект сам (Cargo не следит за папкой, только за уже вшитыми файлами). Если вы добавили файл, измените любой из прежних файлов или Rust-код (достаточно пересохранить `src/main.rs`).

В типах: `LuaSource::Dir(PathBuf)` и `LuaSource::Embedded(EmbeddedLua)`; в `.lua(...)` можно передать `&str`, `String`, `&Path`, `PathBuf` или результат `include_lua!`.

### Ошибки Lua от посетителей

Сообщение об ошибке в обработчике Lua у посетителя в release отправляется на `/_ngs/errors` и передаётся в ваш обработчик:

```rust
App::new().on_client_error(|e| {
    eprintln!("lua error on {} (x{}): {}", e.page, e.count, e.message);
})
```

Поля `ClientError`: `message`, `count` (сколько раз ошибка повторилась с прошлого отчёта), `page` (путь страницы без строки запроса), `user_agent`, `user` (что сохранил `Session::login`, если сессии включены и посетитель вошёл). Структура помечена `#[non_exhaustive]`: создавать её самим нельзя, читайте только поля.

Конечная точка открыта для всех, поэтому она защищена: тело не больше 64 КБ, не более 20 записей в отчёте, сообщение обрезается до 8 КБ, ограничение частоты по умолчанию 30 в минуту на клиента (`client_error_limit`). Обработчик выполняется в задаче запроса: тяжёлую работу (база, HTTP-вызов в систему сбора ошибок) отдайте в `tokio::spawn`. За обратным прокси задайте ограничителю ключ `ClientKey::Forwarded`, иначе все посетители разделят один лимит. В режиме dev браузер не отправляет ошибки, а показывает их на странице. По умолчанию обработчик печатает в stderr.

| Функция | Что включает |
| --- | --- |
| `sqlite` | `security::SqliteStore`: хранение сессий в SQLite (вместе с библиотекой собирается SQLite из исходников, нужен компилятор C) |
| `testing` | модуль `ngs_olezhek::testing` для Lua-тестов, см. [Тестирование](#тестирование) |

### Развёртывание

1. Соберите `cargo build --release`. Лучше встроить Lua через `include_lua!`: тогда нужны только бинарник и папка `public`.
2. Поставьте перед приложением обратный прокси с HTTPS (nginx, Caddy). Сессионная cookie в release защищена флагом `Secure` и работает только по HTTPS.
3. Если за прокси стоит ограничитель частоты, переключите его на `ClientKey::Forwarded { hops: 1 }`, чтобы он видел адрес клиента, а не прокси.
4. Постоянные сессии (чтобы они переживали перезапуск) хранятся в `SqliteStore` или в вашей реализации `SessionStore`.
5. Задайте `App::on_client_error`, чтобы ошибки посетителей попадали в ваши логи.

## Безопасность

### Модель угроз

Фреймворк исходит из такого разделения:

- Код вашего приложения (Lua и Rust) доверенный. Он делает то, что вы написали.
- Недоверенными считаются данные, которые в него попадают: ответы сервера, введённый пользователем текст, параметры адреса (`?next=...`), содержимое базы. Опасность в том, что такие данные попадут туда, где они выполняются как код: в адрес ссылки, в стиль, в атрибут, в HTML.
- Недоверенным может быть и Lua-код, который выполняет ваша страница, если вы запускаете плагины или пользовательские скрипты. Для него есть [песочница](#песочница-для-чужого-кода).
- Исходный код в браузер не отправляется, только байткод. Это затрудняет чтение, но не защита: байткод можно декомпилировать. Не кладите в Lua ключи, пароли и любую логику, которая должна оставаться секретной. Проверки прав, цены, лимиты делайте на сервере.

### Что включено по умолчанию

| Защита | Что делает |
| --- | --- |
| CSRF-проверка | запрос, изменяющий данные и пришедший с чужого сайта, получает `403` |
| Заголовки безопасности | CSP, `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, HSTS в release |
| Текст как текст | `SetText` никогда не интерпретирует HTML, API для вставки HTML нет |
| Проверка адресов | `Link:SetURL`, `Image:SetImage`, `SetAttr` для `href` и `src`, `gui.OpenURL` отклоняют `javascript:` и другие опасные схемы |
| Белые списки | атрибуты, свойства и CSS-свойства задаются только из разрешённых |
| Запрет опасных тегов | собственный класс не может получить `script`, `iframe`, `svg`, `form` и подобные теги |
| Закрытый рантайм | из кода приложения недоступны `debug`, `string.dump`, `dofile`, `loadfile`, бинарный `load`: нельзя добраться до внутренностей фреймворка |
| Заголовки по умолчанию только для своего сайта | `http.SetHeader` не отправляет токены на другие origin |

Не включено и подключается вами: сессии, ограничение частоты, CORS, хеширование паролей.

### CSRF: защита от запросов с чужих сайтов

Атака: пользователь вошёл на ваш сайт, затем открыл вредную страницу, а та тайно отправила `POST` на ваш адрес. Браузер сам приложил cookie сессии, и действие выполнилось бы от имени пользователя.

Защита (тип `CrossOrigin`, включена в `App` для всех маршрутов) работает без токенов:

- `GET`, `HEAD`, `OPTIONS` пропускаются. Это значит, что запрос `GET` не должен менять данные.
- Остальные методы и открытие WebSocket проверяются по заголовкам, которые браузер ставит сам. Если `Origin` в списке доверенных, запрос проходит. Если `Sec-Fetch-Site` равен `same-origin` или `none` (запрос начал сам пользователь), проходит. Любое другое значение (`cross-site`, `same-site`) отклоняется. Для старых браузеров без `Sec-Fetch-Site` сравнивается `Origin` с хостом запроса.
- Запросы без этих заголовков (curl, серверные вызовы, вебхуки) проходят: у них нет «чужих» cookie браузера.
- Проверка работает для всех типов тел: JSON, формы, multipart.

Настройка:

```rust
App::new()
    .trust_origin("https://admin.example.com")
    .csrf(true)
```

`App::csrf(false)` отключает защиту. Делайте это только если то же самое выполняет что-то перед приложением. `App::cors` автоматически добавляет свои origin в доверенные.

### Сессии и вход

Сессия это запись на сервере о том, кто вошёл. Браузеру отдаётся только случайный идентификатор в cookie.

```rust
use ngs_olezhek::security::{Auth, Session, Sessions, password};

let app = App::new().sessions(Sessions::memory());

#[post("/api/login")]
async fn login(session: Session, Json(body): Json<Login>) -> Result<Json<User>, (StatusCode, &'static str)> {
    let user = find_user(&body.name);
    let hash = user.as_ref().map(|u| u.password_hash.as_str());
    if !password::verify(body.password, hash).await {
        return Err((StatusCode::UNAUTHORIZED, "неверное имя или пароль"));
    }
    let user = user.expect("verify passed, so the user exists");
    session.login(user.id).map_err(|_| (StatusCode::INTERNAL_SERVER_ERROR, "сессия не сохранилась"))?;
    Ok(Json(user))
}

#[post("/api/logout")]
async fn logout(session: Session) -> StatusCode {
    session.logout();
    StatusCode::NO_CONTENT
}

#[get("/api/me")]
async fn me(Auth(id): Auth<u64>) -> Json<u64> {
    Json(id)
}
```

Экстракторы:

| Тип | Что даёт |
| --- | --- |
| `Session` | сессия текущего запроса. Изменения сохраняются после возврата из обработчика. Если `App::sessions` не вызван, ответ `500` с подсказкой |
| `Auth<T>` | пользователь, сохранённый через `Session::login`. Если никто не вошёл, обработчик не вызывается, ответ `401 login required` |
| `Option<Auth<T>>` | то же, но без `401`: обработчик получает `None` |

`Session`:

| Метод | Описание |
| --- | --- |
| `login(user)` | сохранить пользователя (число или небольшую структуру `Serialize`) и выдать новый идентификатор сессии. Новая выдача защищает от подстановки чужого идентификатора до входа (session fixation) |
| `logout()` / `destroy()` | удалить сессию из хранилища и cookie из браузера |
| `user::<T>()` | прочитать пользователя |
| `get::<T>(key)`, `insert(key, value)`, `remove(key)`, `clear()` | свои данные в сессии (JSON) |
| `cycle()` | выдать новый идентификатор, сохранив данные. Вызывайте при любом повышении прав |

Свойства сессионной cookie: `HttpOnly` (скрипты страницы её не видят), `SameSite=Lax`, в release `Secure` и префикс `__Host-` (имя `__Host-ngs-session`; в dev имя `ngs-session` без `Secure`, чтобы работало по `http://localhost`). Сессия создаётся только когда в неё что-то записали, поэтому анонимные посетители не заполняют хранилище. Ответы, в которых выдаётся cookie, получают `Cache-Control: no-store`.

Настройка `Sessions`:

| Метод | По умолчанию | Описание |
| --- | --- | --- |
| `Sessions::new(store)` / `Sessions::memory()` | | хранилище. `memory()` живёт до перезапуска сервера |
| `.secure(bool)` | `!dev` внутри `App` | cookie только по HTTPS |
| `.same_site(SameSite::Strict / Lax / None)` | `Lax` | `None` всегда включает `Secure` |
| `.idle_timeout(Duration)` | 1 день | сессия кончается после такого простоя |
| `.lifetime(Duration)` | 30 дней | абсолютный срок жизни сессии с момента создания (или входа) |
| `.cookie_name(name)` | `__Host-ngs-session` или `ngs-session` | имя cookie |

Хранилища:

- `MemoryStore` в памяти процесса. Подходит для одного сервера, теряется при перезапуске.
- `SqliteStore` (функция `sqlite`) хранит сессии в файле SQLite. Конструкторы: `SqliteStore::open(path)`, `in_memory()`, `from_connection(conn)`, `with_table(conn, name)`; метод `sweep()` удаляет просроченные записи (это и так делается раз в десять минут).
- Свою реализацию (Redis, PostgreSQL) делайте через трейт `SessionStore` с тремя методами `load`, `save`, `delete`. Ключ хранилища это SHA-256 от cookie, поэтому утечка базы или бэкапа не даёт рабочих cookie.

```rust
Sessions::new(SqliteStore::open("sessions.db")?).idle_timeout(Duration::from_secs(3600))
```

Если хранилище недоступно, запрос получает `503`.

Клиентская проверка входа в Lua (`Guard` на странице, скрытие кнопок) нужна для удобства, а не для защиты: её можно обойти. Все права проверяйте на сервере через `Auth<T>`.

### Пароли

`security::password` использует Argon2id с рекомендованными OWASP параметрами (19 МиБ памяти, 2 прохода, 1 поток).

| Функция | Описание |
| --- | --- |
| `password::hash(password).await` | возвращает строку формата PHC (`$argon2id$...`) со случайной солью, готовую к хранению в базе |
| `password::verify(password, hash: Option<&str>).await` | возвращает `bool`. Если `hash` равен `None` (пользователя нет), всё равно выполняется полная проверка по заготовленному хешу: по времени ответа нельзя узнать, существует ли логин |

Обе функции работают в отдельном пуле потоков: хеширование занимает десятки миллисекунд намеренно.

### Ограничение частоты

`RateLimit` это слой (`tower::Layer`), который отвечает `429 Too Many Requests` с заголовком `Retry-After`, если клиент шлёт запросы слишком часто. Алгоритм GCRA: `count` запросов за `period`, но не более `burst` подряд.

```rust
App::new()
    .api(routes![login].layer(RateLimit::per_minute(5)))
    .api(routes![search].layer(RateLimit::per_second(10).burst(20)))
```

| Метод | Описание |
| --- | --- |
| `RateLimit::new(count, period)`, `per_second(n)`, `per_minute(n)`, `per_hour(n)` | задать лимит. `count` не может быть 0 |
| `.burst(n)` | сколько запросов подряд допускается до перехода на ровный темп (по умолчанию `count`) |
| `.key(ClientKey)` | по чему считать клиентов |
| `.check(key)` | ручной вызов вне слоя: `Err(Duration)` говорит, сколько ждать |

Копии `RateLimit` делят счётчики, поэтому один лимит можно повесить на несколько групп маршрутов. Ключ клиента:

| `ClientKey` | Что считается клиентом |
| --- | --- |
| `Peer` (по умолчанию) | адрес TCP-соединения. За обратным прокси все клиенты выглядят как прокси |
| `Forwarded { hops }` | адрес из `X-Forwarded-For`, который записал последний из `hops` доверенных прокси. Записи левее считаются подделанными и игнорируются |
| `Header(name)` | значение заголовка, например ключ API |
| `Custom(fn)` | любое значение из запроса (идентификатор пользователя и т. д.); при `None` берётся адрес |

### CORS

По умолчанию страницы с других сайтов не могут читать ответы вашего API. Если нужно разрешить это (например, отдельному сайту-админке), включите CORS:

```rust
App::new().cors(Cors::origins(["https://admin.example.com"]).credentials(true))
```

| Метод | Описание |
| --- | --- |
| `Cors::origins([...])` | точный список адресов вида `https://host[:port]`. Подстановки `*` нет намеренно; неверное значение вызывает панику при запуске |
| `.credentials(bool)` | разрешить отправку cookie с межсайтовыми запросами (по умолчанию нет) |
| `.allow_header(HeaderName)` | ещё один разрешённый заголовок (по умолчанию `Content-Type` и `Authorization`) |
| `.max_age(Duration)` | сколько браузер кеширует ответ на предварительный запрос (по умолчанию час) |

Разрешены методы `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`. Указанные origin автоматически добавляются в доверенные для CSRF. Не забудьте и про CSP (`connect-src`): без него браузер не позволит вашей странице обращаться к другому адресу.

### Политика безопасности контента (CSP)

CSP это заголовок, в котором сервер перечисляет, откуда странице можно загружать ресурсы. Он ограничивает ущерб, если в страницу всё же проникнет чужой код. Политика по умолчанию (константа `DEFAULT_CSP`):

```text
default-src 'self'; script-src 'self' 'wasm-unsafe-eval' 'sha256-<хеш загрузочного скрипта>';
style-src 'self'; img-src 'self' data: blob:; connect-src 'self'; object-src 'none';
base-uri 'none'; frame-ancestors 'none'; form-action 'self'
```

Последствия, о которых нужно знать:

- Картинки, шрифты, стили и запросы (`fetch`, WebSocket, SSE) разрешены только с вашего сайта. Картинка с чужого адреса (`Image:SetImage("https://cdn.example.com/a.png")`) пройдёт проверку схемы, но браузер её заблокирует.
- Страницу нельзя встроить в `iframe` на чужом сайте (`frame-ancestors 'none'` и `X-Frame-Options: DENY`).
- Чтобы разрешить внешний ресурс, расширьте политику:

```rust
use ngs_olezhek::{App, DEFAULT_CSP, axum::http::HeaderValue};

let csp = DEFAULT_CSP.replace("img-src 'self' data: blob:", "img-src 'self' data: blob: https://cdn.example.com");
let app = App::new().content_security_policy(HeaderValue::from_str(&csp).unwrap());
```

### Безопасность в Lua

Что фреймворк проверяет за вас, и что остаётся на вас:

- Данные в `SetText` безопасны. Данные в адресах проверяются (`Link:SetURL`, `Image:SetImage`, `SetAttr("href")`), недопустимая схема отклоняется с сообщением об ошибке: `Link:SetURL` возвращает `false`, ссылка остаётся без адреса.
- Адреса, пришедшие из внешних данных, всё равно показывайте пользователю так, чтобы было видно, куда он перейдёт. Допустимая схема `https:` ещё не значит, что сайт безопасен.
- `SetStyle` не принимает `url()`, CSS-функции вне списка и символы `\ ; { } < >`: из стиля нельзя заставить браузер что-то скачать или вставить лишние правила.
- `SetAttr` принимает атрибуты только из белого списка и не принимает `on*`, `style`, `srcdoc`, `formaction`, `target`. `SetProp` и `Invoke` тоже по спискам.
- Классы с собственным тегом не могут использовать `script`, `style`, `link`, `meta`, `base`, `iframe`, `frame`, `object`, `embed`, `applet`, `template`, `noscript`, `svg`, `math`, `portal`, `form`.
- Из приложения удалены `debug`, `string.dump`, `dofile`, `loadfile`; `load` принимает только текстовые куски. Поэтому код приложения (и библиотеки, которые вы подключили) не может достать внутренние таблицы рантайма.
- `storage` читается любым скриптом страницы. Секретные токены кладите в cookie с `HttpOnly` на стороне сервера, а не в `storage`.
- Не вызывайте `load` с текстом из недоверенного источника: он выполнится с правами вашего приложения. Для чужого кода есть `sandbox.New`.

### Чек-лист перед запуском

- Режим release (`cargo build --release`) и HTTPS перед приложением.
- Сессии с постоянным хранилищем; пароли только через `password::hash`.
- На входе и на других «дорогих» маршрутах стоит `RateLimit`, а за прокси он использует `ClientKey::Forwarded`.
- Все изменения данных идут через `POST`, `PUT`, `PATCH` или `DELETE`, а не через `GET`.
- Права проверяются на сервере (`Auth<T>`), а не только в `Guard`.
- В `content_security_policy` перечислены только нужные внешние источники.
- `on_client_error` пишет ошибки браузеров в ваш журнал.
- В Lua-коде нет секретов.

## Песочница для чужого кода

Иногда на странице нужно выполнить код, который написали не вы: плагин, пользовательский скрипт, формула. `sandbox.New` запускает его в отдельной виртуальной машине Lua, у которой нет ничего общего с приложением.

```lua
local box = sandbox.New({
    name = "plugin",
    root = container,
    instructions = 1000000,
    memory = 4 * 1024 * 1024,
    api = {
        add = function(a, b) return a + b end,
    },
    on_print = function(text) print("[plugin] " .. text) end,
    on_error = function(message) ui.Toast("Ошибка плагина: " .. message) end,
})

local ok, err = box:Run(source, "plugin.lua")
if not ok then print(err) end
```

Что видит плагин: другая таблица глобальных переменных. В ней нет `http`, `storage`, `cookie`, `router`, `debug` и ваших глобалов. Данные между приложением и плагином только копируются (числа, строки, булевы значения, таблицы без функций и метатаблиц), общих таблиц нет.

### Параметры sandbox.New

| Ключ | По умолчанию | Описание |
| --- | --- | --- |
| `name` | `"sandbox"` | имя для сообщений об ошибках |
| `root` | нет | пустая панель, в которой плагин строит свой интерфейс. Без неё у плагина нет `ui` |
| `api` | пусто | функции, которые плагин может вызвать как `api.имя(...)`. Принимают и возвращают только простые данные |
| `classes` | базовые элементы и раскладки | какие классы панелей плагин может создавать. По умолчанию `Panel`, `Label`, `Button`, `TextEntry`, `CheckBox`, `ComboBox`, `Slider`, `NumberWang`, `ProgressBar`, `Row`, `Column`, `Grid`, `ScrollPanel` |
| `instructions` | 2 000 000 | сколько инструкций Lua разрешено за один `Run`, `Call` и обработку одного события. При превышении выполнение прерывается |
| `memory` | 8 МиБ | потолок памяти виртуальной машины |
| `max_panels` | 500 | сколько панелей плагин может создать |
| `on_error` | вывод ошибки | функция для ошибок в событиях и таймерах |
| `on_print` | вывод в консоль | функция для `print` плагина |

Лимиты принадлежат виртуальной машине, поэтому создавайте отдельный `sandbox.New` для каждого плагина: так один плагин не расходует бюджет другого.

### Методы sandbox

| Метод | Описание |
| --- | --- |
| `box:Run(source, [name])` | выполнить текст (не байткод). Возвращает `true` или `false, сообщение` |
| `box:Call(name, ...)` | вызвать глобальную функцию, которую определил плагин. Аргументы и результаты копируются. Возвращает `true, результаты...` или `false, сообщение` |
| `box:Expose(name, fn)` | добавить функцию в `api` после создания |
| `box:Close()` | удалить панели плагина и освободить машину. То же происходит, когда удаляют `root` |
| `box:IsClosed()` | закрыта ли |

### Что доступно плагину

Внутри песочницы есть:

- `print(...)`, `api.имя(...)`, `Color(r, g, b, a)`, `IsValid(panel)`;
- `timer.Simple(delay, fn)` (не больше 64 ожидающих таймеров);
- `ui.Create(class, [parent], [props])`, `ui.Root()`, `ui.IsPanel(v)` (если есть `root`);
- стандартные безопасные библиотеки Lua (`string`, `table`, `math`...) без опасных функций.

Панели в плагине это прокси: вызов метода уходит в приложение, где он проверяется. Разрешены методы на `Set`, `Get`, `Is`, `Has` (`SetText`, `GetValue`...) и несколько других: `Dock`, `DockMargin`, `DockPadding`, `Center`, `Clear`, `Remove`, `Show`, `Hide`, `Toggle`, `AddChoice`, `ChooseOption`, `ChooseOptionID`, `RequestFocus`, `KillFocus`, `SizeToContents*`, `InvalidateLayout`, `ChildCount`, `MoveTo`, `SizeTo`, `AlphaTo`, `ScrollToChild`. Запрещены `SetParent`, `SetSlot`, `SetOutlet`, `SetRichTooltip`, `SetPaintEveryFrame`, `SetDataSource` (они принимают панели и функции или тратят ресурсы каждый кадр). Свойства при создании (`{ Text = "Hi" }`) работают через те же методы. Обработчики событий (`OnValueChanged`, `DoClick`...) плагин назначает как поля панели, они вызываются с копиями данных.

Корневая панель `root` принадлежит приложению. Плагин может её читать и очищать (`GetSize`, `GetChildren`, `Clear`...), но не изменять. Ей автоматически задаётся обрезка по границам, чтобы плагин не мог рисовать поверх остального интерфейса.

Ограничения: за один запуск разрешено до 10 000 обращений к приложению; вложенные вызовы ограничены; через границу таблица может быть вложена не более чем на 32 уровня и содержать не более 100 тысяч элементов.

### Пример: плагин-счётчик

Плагин (текст, например, от пользователя):

```lua
local root = ui.Root()
local label = ui.Create("Label", root, { Text = "Нажато: 0" })
local n = 0
ui.Create("Button", root, {
    Text = "Кликни",
    DoClick = function()
        n = n + 1
        label:SetText("Нажато: " .. n)
    end,
})
```

Хост создаёт для него панель и запускает:

```lua
local stage = ui.Create("Row", card, { Gap = 8 })
local box = sandbox.New({ name = "counter", root = stage })
local ok, err = box:Run(plugin_source, "counter")
```

Бесконечный цикл (`while true do end`) оборвётся по лимиту инструкций, слишком большой массив по лимиту памяти, а попытка создать `Frame` или вызвать `label:SetParent(nil)` даст ошибку. Пример с редактором плагина лежит в `examples/hello/lua/lazy/security.lua`.

## Тестирование

Lua-интерфейс можно проверять обычным `cargo test`, без браузера. Фреймворк запускает ваш Lua-код на настоящем рантайме с подменённым браузером: поддельное дерево элементов, часы, `fetch` и хранилище. Тест кликает по кнопкам, печатает в полях, отвечает на запросы и проверяет результат.

### Подключение

```toml
[dev-dependencies]
ngs_olezhek = { path = "../ngs_olezhek", features = ["testing"] }
```

```rust
// tests/ui.rs
use ngs_olezhek::testing::LuaTests;

#[test]
fn lua() {
    LuaTests::new("lua").run_dir("tests/lua");
}
```

`LuaTests::new` принимает ту же папку, что `App::lua` (относительно корня крейта). Файлы тестов положите в отдельную папку вне `lua/`, иначе они попадут в приложение.

### Тестовый файл

```lua
test("empty name is caught before the request", function(t)
    t.Go("/")
    t.Click({ Class = "Button", Text = "Сохранить" })
    t.Eq(t.Get("#name"):GetError(), "Обязательное поле")
    t.Eq(#t.Requests("POST /api/users/1/rename"), 0)
end)

test("search shows results", function(t)
    t.Serve("GET /api/search", function(req)
        return { { id = 2, name = "Гарри", role = "player" } }
    end)
    t.Go("/")
    t.Type("#search", "Гар")
    assert(t.HasText("Гарри"), t.Text())
end)
```

`test(name, function(t) ... end)` регистрирует случай. Каждый случай выполняется в новом рантайме, в котором уже отработал `autorun`. Страница не показана, пока тест не вызовет `t.Go(url)`. Провал одного случая не останавливает остальные: в конце тест Rust падает с отчётом по всем. Для каждого случая печатается строка `lua test файл :: имя ... ok` или `... FAILED` (при успехе её видно с флагом `cargo test -- --nocapture`).

Сообщения об ошибках рантайма (`ErrorNoHalt`, исключения в обработчиках), которые тест не забрал через `t.Errors()`, считаются провалом.

### Помощники теста (`t`)

Страницы и поиск:

| Функция | Описание |
| --- | --- |
| `t.Go(url)` | открыть страницу (первый вызов запускает приложение, дальше как `router.Go`). Возвращает страницу |
| `t.Page()`, `t.Path()` | текущая страница; текущие путь и строка запроса |
| `t.Find(query, [root])` | первая панель, подходящая под запрос, или `nil` |
| `t.FindAll(query, [root])` | все подходящие |
| `t.Get(query, [root])` | как `Find`, но провалит тест и покажет тексты на экране, если ничего не нашлось |
| `t.Text([root])`, `t.HasText(text, [root])` | все непустые тексты (по строке на текст); есть ли такой фрагмент |

Запрос (`query`): строка с именем класса (`"Button"`, подходят и наследники), строка `"#имя"` (панель с таким `SetName`), таблица условий `{ Class = "Button", Name = "email", Text = "Сохранить", Contains = "Сох", Visible = true }` (все условия сразу) или функция-предикат `function(panel) return ... end`.

Действия пользователя:

| Функция | Описание |
| --- | --- |
| `t.Click(panel_or_query)` | клик. На отключённой панели ничего не происходит |
| `t.Type(panel_or_query, text)` | заменить текст поля, как будто он напечатан (срабатывают `OnChange`, `OnValueChange`, привязки) |
| `t.Press(panel_or_query, key)` | нажать клавишу (`"Enter"`, `"Escape"`...) |
| `t.Select(panel_or_query, option)` | выбрать пункт `ComboBox` по тексту или номеру |
| `t.Check(panel_or_query, [on])` | поставить или снять флажок (по умолчанию поставить) |

Сеть, время, браузер:

| Функция | Описание |
| --- | --- |
| `t.Serve(pattern, answer)` | поддельный маршрут сервера, отвечает автоматически. `answer` значение (уйдёт как JSON со статусом 200) или функция `function(req, params)`, возвращающая значение или `статус, тело` |
| `t.Requests([pattern])` | запросы, сделанные к этому моменту |
| `t.Request(pattern)` | самый старый запрос без ответа (если такого нет, тест провален) |
| `t.Respond(pattern, [status], body, [content_type])` | ответить на запрос вручную |
| `t.Fail(pattern, [message])` | ответить сетевой ошибкой |
| `t.Advance(seconds)` | передвинуть поддельные часы: сработают таймеры, `Timer`, тайм-ауты запросов |
| `t.Stream(pattern)` | последнее WebSocket- или SSE-соединение; у него поля `sent`, `closed` и метод `Emit(event, text)` |
| `t.Clipboard()` | что записано в буфер обмена |
| `t.Storage([session])` | содержимое `localStorage` (или `sessionStorage` при `true`) |
| `t.Errors()` | забрать накопленные ошибки рантайма |
| `t.Settle()` | выполнить отложенную работу (загрузку ленивых модулей, перерисовку) |
| `t.Eq(actual, expected, [message])` | сравнение значений, таблицы по содержимому |
| `t.MOCK` | состояние подделки (элементы, запросы, таймеры) для особых проверок |

Шаблон адреса (`pattern`): `"GET /api/users/{id}"` или `"/api/users/1"`. Метод необязателен, строка запроса игнорируется, если её нет в шаблоне, `{id}` подставляется параметрами (`params`), `{*rest}` забирает остаток. Вместо строки можно дать функцию-предикат.

Запрос (`TestRequest`), который видит тест: `method`, `url`, `body`, `json` (тело, разобранное как JSON), `query` (значения из адреса), `headers`.

### Rust API

| Тип | Описание |
| --- | --- |
| `LuaTests::new(lua_dir)` | тестовый запуск для папки приложения |
| `.filter(text)` | выполнять только случаи, в имени которых есть `text`. То же делает переменная окружения `NGS_TEST` |
| `.run_dir(dir)` | все `.lua` из папки, рекурсивно. Паникует с отчётом при провалах |

| `.run(name, source)` | тест, заданный строкой |

| `Runtime::new()` | рантайм без файлов приложения |

### Чего тесты не умеют

Подмена проще настоящего браузера. Размеры всех панелей фиксированы (100 на 50 пикселей) и реальной раскладки нет, поэтому `GetSize` и `PerformLayout` бесполезны для проверки вёрстки; `Paint` ничего не рисует; наведение мыши и фокус не эмулируются. Тесты проверяют логику: что показывается, как реагирует на ввод, какие запросы уходят. Внешний вид проверяйте в браузере.

## Инструменты разработчика

### Автодополнение в редакторе

В режиме dev при `serve` сервер записывает рядом с вашим Lua-кодом папку `.ngs` (только если её содержимое изменилось):

| Файл | Что внутри |
| --- | --- |
| `.ngs/ngs.lua` | описание всего Lua API фреймворка: функции, классы, константы, подсказки по параметрам |
| `.ngs/testing.lua` | описание `t` и `test` для Lua-тестов |
| `.ngs/api.lua` | типы ваших Rust-структур с `#[derive(LuaType)]` |

В корне проекта (там, где `Cargo.toml`) создаётся `.luarc.json`, если его нет: он подключает `.ngs` как библиотеку для [Lua Language Server](https://luals.github.io) (расширение «Lua» в VS Code). После этого редактор подсказывает методы и параметры, подсвечивает опечатки в именах и показывает документацию. Если `.luarc.json` у вас уже есть, добавьте в `workspace.library` путь `lua/.ngs`. Папку `.ngs` стоит добавить в `.gitignore`.

Свои классы описываются комментариями `---@class`. Тогда `ui.Create("Card", ...)` в редакторе возвращает `Card`:

```lua
---@class Card: Panel
---@field TitleLabel Label
local CARD = {}

---@param text string
function CARD:SetTitle(text)
    self.TitleLabel:SetText(text)
end
```

Тип данных от сервера указывается так: `---@param user User`.

### Типы из Rust: #[derive(LuaType)]

Структура, которую ваш сервер отдаёт в JSON, превращается в описание для редактора:

```rust
use ngs_olezhek::LuaType;
use serde::Serialize;

#[derive(Serialize, LuaType)]
struct User {
    id: u64,
    /// Отображаемое имя
    name: String,
    nickname: Option<String>,
    roles: Vec<String>,
}
```

Результат в `.ngs/api.lua`:

```lua
---@class User
---@field id integer
---@field name string Отображаемое имя
---@field nickname? string
---@field roles string[]
```

В Lua: `---@param user User`, и редактор знает поля. В описание попадают комментарии `///` к типам, полям и вариантам.

Типы учитывают атрибуты `serde`, потому что описывают форму JSON: `rename`, `rename_all`, `skip` и `skip_serializing`, `skip_serializing_if` (поле станет необязательным), `flatten`, `transparent`, `untagged`, `tag`, `content`. Дополнительные атрибуты `#[lua(...)]`:

| Атрибут | Где | Что делает |
| --- | --- | --- |
| `#[lua(name = "...")]` | тип, поле, вариант | другое имя в Lua |
| `#[lua(type = "string\|number")]` | поле | задать тип вручную |
| `#[lua(optional)]` | поле | пометить необязательным |
| `#[lua(skip)]` | поле, вариант | не включать |

Соответствие типов Rust типам Lua:

| Rust | Lua |
| --- | --- |
| `bool` | `boolean` |
| целые (`i32`, `u64`, `usize`, `NonZero*`...) | `integer` |
| `f32`, `f64` | `number` |
| `String`, `&str`, `char`, `PathBuf`, `Uuid`, типы даты и времени `chrono` и `time`, IP-адреса, `Url`, `Decimal` | `string` |
| `Option<T>` | `T?` (поле необязательное) |
| `Vec<T>`, `HashSet<T>`, `BTreeSet<T>`, массивы, срезы | `T[]` |
| `HashMap<K, V>`, `BTreeMap<K, V>` | `table<string, V>` |
| `serde_json::Value` | `any` |
| `Box<T>`, `Rc<T>`, `Arc<T>`, `Cow<T>`, `Mutex<T>`, `axum::Json<T>` | как `T` |
| `Duration` | `{ secs: integer, nanos: integer }` |
| кортежи | `[A, B]` |
| `()` | `nil` |
| перечисления | `---@alias` с вариантами с учётом `tag`, `content`, `untagged` |

В `.ngs/api.lua` попадают типы, которые вошли в сборку. Если нужно записать файл в другое место (проверка в CI, коммит в репозиторий), вызовите `ngs_olezhek::lua_types()`: она вернёт текст файла.

```rust
std::fs::write("types/api.lua", ngs_olezhek::lua_types()).unwrap();
```

### Отличия от Garry's Mod

Фреймворк узнаваем для тех, кто писал интерфейсы в Garry's Mod, но это не GLua:

- Пространство имён `ui` вместо `vgui`: `ui.Create`, `ui.Register`. Имена классов без префикса `D` (`Frame`, `Button`, `Label`, `TextEntry`).
- Синтаксис обычного Lua 5.4: `~=`, `--`, `and`/`or`/`not`. Нет `!=`, `&&`, `//`, `continue`.
- Нет `Vector`, `Angle`, `net`, `file`, `sql` и другого серверного и игрового API. `Material(url)` загружает картинку по адресу, а не материал игры. Вместо `continue` используйте `goto continue`.
- Раскладка не vgui-вычисляемая, а CSS: `Dock` реализован через сетку, `SetPos` через абсолютное позиционирование, много методов, которых нет в Garry's Mod (`SetLayout`, `SetGap`, `SetStyle`...).
- `Paint` рисует на `<canvas>` и вызывается только при инвалидации, а не каждый кадр.
- Запросы к серверу `http.*` ждут ответа прямо в обработчиках, так как они работают в корутинах.

## Решение проблем

### Сборка

| Симптом | Причина и решение |
| --- | --- |
| `wasm-bindgen not found` | поставьте: `cargo install wasm-bindgen-cli --version 0.2.129` |
| ошибка о несовпадении версий `wasm-bindgen` | версия CLI должна быть ровно `0.2.129` |
| `can't find crate for core` / нет цели `wasm32-unknown-unknown` | `rustup target add wasm32-unknown-unknown` |
| `wasm-opt unavailable or failed, shipping unoptimized runtime` | это предупреждение, а не ошибка: поставьте `binaryen`, чтобы рантайм стал меньше |
| сборка рантайма невозможна на этой машине | задайте `NGS_RUNTIME_DIR` с готовыми `runtime.js` и `runtime_bg.wasm` |
| Windows: `LNK1104` при `cargo test`, когда запущен пример | пример держит свой `.exe` открытым. Остановите его перед сборкой |
| ошибка в `include_lua!` с текстом `lua: ...` | синтаксическая ошибка в Lua-файле; сообщение содержит имя файла и строку |
| добавили Lua-файл, а в сборке его нет | Cargo не следит за новыми файлами в папке: пересохраните любой Rust-файл |

### Запуск

| Симптом | Причина и решение |
| --- | --- |
| Сервер не стартует с `lua compile errors` | в release синтаксическая ошибка останавливает запуск. Исправьте файл из сообщения |
| Сервер пишет `lua dir ...: ...` | папка Lua не найдена. Путь считается от текущей папки процесса, запускайте из корня проекта или используйте `include_lua!` |
| Белая страница | откройте консоль браузера (F12). Частые причины: рантайм не загрузился (смотрите вкладку Network), политика безопасности блокирует ресурс (в консоли строка `Content Security Policy`), ошибка в стартовом Lua-коде |
| Страница не обновляется после правки | горячая перезагрузка работает только в dev. Проверьте, что соединение `/_ngs/live` не блокируется прокси |
| На новой странице `404`, хотя файл есть | для `lazy/` адрес берётся из имени файла; файл должен возвращать определение страницы. Для адреса с параметрами нужен `router.Lazy` в `autorun/` |

### Ошибки в Lua

| Сообщение | Причина и решение |
| --- | --- |
| `this call waits for a result, so it only works inside handlers and Initialize` | вы вызвали `http.Get`, `Form:Submit` и т. п. вне обработчика (например, в `Paint`, в таймере из `timer.Simple` вне панели или в корне файла). Используйте `http.Fetch` с обратными вызовами или перенесите вызов в обработчик |
| `unknown panel class 'X'` | класс не зарегистрирован или файл с ним выполнился позже. Базовые классы кладите в файлы, которые идут раньше, или в `autorun/` |
| `style property 'x' is not allowed` | свойства нет в белом списке; расположение задаётся `SetPos`, `Dock`, `SetLayout` |
| `style value ... uses url(), which is not allowed` | `url()` в стилях запрещена; картинки показывайте через `Image` |
| `attribute 'x' is not allowed` | атрибута нет в белом списке. Атрибуты `on*` намеренно запрещены, пользуйтесь методами панели |
| `blocked URL with scheme 'javascript'` | адрес с опасной схемой. Допустимы `http`, `https`, `mailto` (для картинок ещё `data`, `blob`) и относительные |
| `attempt to call a nil value (method 'X')` | у панели нет такого метода: опечатка, не тот класс или метод есть у другого класса |
| `panel class 'X' inherits from itself` | цикл в `Base` |
| `native tag <x> is not allowed` | запрещённый HTML-тег в поле `Tag` |
| `Bind: ... has no default property` | у класса нет `BindDefault`, передайте имя свойства: `Bind("Text", state)` |
| `ui.State: effects keep changing the state they read (a cycle?)` | эффекты по кругу меняют то, что читают |

### Поведение

| Симптом | Причина и решение |
| --- | --- |
| `DoClick` на надписи не срабатывает | у `Label` по умолчанию отключена реакция на мышь: `label:SetMouseInputEnabled(true)` |
| У панели с `Paint` пропали фон и рамка | при наличии `Paint` обычный фон не показывается: рисуйте его сами |
| `Paint` не вызывается после изменения данных | вызовите `InvalidatePaint()` |
| После смены темы холст остался в старых цветах | `Paint` не видит CSS-переменные: берите цвета через `ui.GetVar`, тогда `ui.SetVars` перерисует панель с новыми |
| Нужны свои панели во всплывающем меню | `Menu` принимает только пункты; для произвольного содержимого есть `Popover` |
| `Initialize` не выполняется заново при смене данных | `Initialize` вызывается один раз. Используйте `Rebuild()`, привязки (`Bind`) или `UseQuery` |
| Таблица `DataGrid` пустая или схлопнулась | ей нужна высота: `Dock = DOCK_FILL`, `SetTall` или `SetGrow` |
| Дети вылезают за границы родителя | дети не сжимаются. Поставьте родителю `ScrollPanel`, ограничьте размеры или включите `SetLayoutWrap(true)` |
| Кнопка растянулась на всю ширину | в столбце дети растягиваются по умолчанию: `parent:SetAlign(ALIGN_START)`, `child:SetAlignSelf(ALIGN_START)` или `SetWide(...)` |
| Две панели с `Dock` перекрывают друг друга | порядок создания определяет, кто какую сторону получил; последней создавайте `DOCK_FILL` |
| Картинка с другого сайта не показывается | CSP по умолчанию разрешает только свой сайт, см. [Безопасность](#безопасность) |
| Шрифт не загружается | файл должен лежать на вашем сайте (`App::public`) и адрес в `url` должен быть верным; следите за `surface.IsFontLoaded` |
| `403 cross-origin request blocked` | CSRF-проверка отклонила запрос с чужого origin. Добавьте `App::trust_origin` или `App::cors`, если это ваш второй сайт |
| `404 no such endpoint` в `err.message` | сервер вернул страницу-оболочку: такого API-адреса нет. Проверьте путь и префикс `api_prefix` |
| `429` | сработал `RateLimit`; в заголовке `Retry-After` сколько ждать |
| `503 session store unavailable` | не отвечает хранилище сессий |
| Вход не запоминается в release | cookie с `Secure` не сохраняется по `http://`. Нужен HTTPS (или `Sessions::secure(false)` только для тестов) |
| `clipboard.ReadText` возвращает ошибку | браузеру нужно разрешение и HTTPS (или `localhost`); вызывайте из обработчика клика |
| Тест не видит нужный размер или рисунок | в тестовом окружении размеры фиксированы, `Paint` не рисует |

### Ограничения

- Только Lua 5.4 без `io`, `os`, `package`, `bit32`, `debug`.
- Нет HTML-вставок и произвольных CSS: всё через белые списки.
- Поиск и индексирование страниц роботами, которые не выполняют WebAssembly, ограничены: им видны заголовок и метатеги из `App::title` и `App::meta`, но не содержимое страниц.
- Приложение не работает без WebAssembly в браузере (все современные браузеры поддерживают).
- Размер загрузки включает рантайм с интерпретатором Lua. В release он собирается с оптимизацией по размеру и отдаётся со сжатием.
- Исходный Lua-код скрыт байткодом, но не защищён от анализа.
